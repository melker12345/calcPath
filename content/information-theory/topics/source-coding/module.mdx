# Source Coding & Compression

The AEP, Shannon's source coding theorem, and practical lossless compression algorithms.

Compression is the problem of writing down what a random source produced using as few bits as possible. Shannon's answer, and the subject of this chapter, is that the question has an exact numerical answer: a source with entropy rate $h$ can be described with $h$ bits per symbol and cannot be described with fewer. Everything else — Huffman trees, arithmetic coders, dictionary methods — is engineering in the neighbourhood of that number.

The chapter is organised as a single argument. We first prove the *asymptotic equipartition property* (AEP), the information-theoretic law of large numbers, and use it to isolate a small set of sequences carrying almost all the probability. Counting that set proves Shannon's source coding theorem in both directions. We then descend from block codes to symbol codes, where Kraft's inequality replaces the counting argument and yields the fundamental bound $H \le L < H+1$. The second half of the chapter is about closing that one-bit gap (arithmetic coding) and about what to do when the source distribution is unknown (Lempel–Ziv and universal coding).

Throughout, $\mathcal{X}$ is a finite alphabet, $X_1, X_2, \dots$ is a stochastic process taking values in $\mathcal{X}$, $x^n = (x_1,\dots,x_n)$ denotes a string of length $n$, and $\log$ means $\log_2$, so that all information is measured in bits.

## The Law of Large Numbers for Information {#definition}

<!-- section: definition -->

Entropy was introduced as the expected surprise of a single draw. To say anything about *files* we need a per-symbol quantity that survives dependence between symbols.

:::definition[Entropy rate]{#entropy-rate}
The **entropy rate** of a stochastic process $\{X_i\}$ is

$$h = \lim_{n\to\infty} \frac{1}{n} H(X_1,\dots,X_n),$$

whenever the limit exists. For a stationary process the limit always exists and also equals $\lim_{n\to\infty} H(X_n \mid X_1,\dots,X_{n-1})$, the conditional entropy of the next symbol given the entire past.
:::

For an i.i.d. source the chain rule gives $H(X_1,\dots,X_n) = nH(X)$ immediately, so $h = H(X)$: the entropy rate is the ordinary single-symbol entropy. For a source with memory the two differ, and the difference is exactly the redundancy that a model of the memory can harvest.

:::definition[Sample information rate]{#sample-information-rate}
For a string $x^n$ of positive probability, the **sample information rate** is

$$-\frac{1}{n}\log p(x^n),$$

the number of bits per symbol an ideal code would spend on this particular string. The random variable $-\frac1n \log p(X^n)$ is the empirical rate of the string actually produced.
:::

The entropy rate is an expectation, $h = \lim \frac1n E[-\log p(X^n)]$; the sample information rate is the random quantity being averaged. The AEP says that the random quantity concentrates on its mean — that essentially every long string costs the same number of bits per symbol.

:::theorem[Weak law of large numbers]{#wlln}
If $Y_1, Y_2,\dots$ are i.i.d. with finite mean $\mu$, then $\frac1n\sum_{i=1}^n Y_i \to \mu$ in probability: for every $\varepsilon > 0$,

$$\Pr\!\left( \left| \frac1n\sum_{i=1}^n Y_i - \mu \right| \ge \varepsilon \right) \longrightarrow 0 \qquad (n\to\infty).$$
:::

:::proof
We prove the case of finite variance $\sigma^2$, which is all we need here: a finite alphabet makes $-\log p(X)$ a bounded random variable. The sample mean $\bar Y_n$ has mean $\mu$ and, by independence, variance $\sigma^2/n$, so Chebyshev's inequality gives

$$\Pr\!\left( |\bar Y_n - \mu| \ge \varepsilon \right) \le \frac{\sigma^2}{n\varepsilon^2} \longrightarrow 0 .$$

(The general finite-mean case is Khinchin's theorem and requires a truncation argument, which we do not need.)
:::

:::theorem[Asymptotic equipartition property, i.i.d. case]{#aep}
Let $X_1,X_2,\dots$ be i.i.d. with probability mass function $p$ on a finite alphabet, and write $H = H(X)$. Then

$$-\frac{1}{n}\log p(X_1,\dots,X_n) \longrightarrow H \quad \text{in probability.}$$
:::

:::proof
Independence factorises the joint mass function, $p(X^n) = \prod_{i=1}^n p(X_i)$, and the logarithm turns the product into a sum:

$$-\frac1n \log p(X^n) = \frac1n \sum_{i=1}^n \bigl(-\log p(X_i)\bigr).$$

The summands $Y_i = -\log p(X_i)$ are i.i.d. functions of i.i.d. variables, and are bounded because the alphabet is finite and every symbol that can actually be observed has $p(x)>0$. Their common mean is

$$E[Y_1] = \sum_{x} p(x)\bigl(-\log p(x)\bigr) = H(X).$$

The weak law of large numbers applied to $Y_1,Y_2,\dots$ now gives $\frac1n\sum_i Y_i \to H(X)$ in probability, which is the claim.
:::

That proof is worth rereading, because it is the whole trick: **the AEP is the weak law of large numbers applied to the random variable "surprise".** Everything in the first half of this chapter is a consequence of it.

:::remark[Beyond independence]
For a general stationary ergodic process the same conclusion holds, in the stronger almost-sure form

$$-\frac1n\log p(X^n) \longrightarrow h \quad \text{almost surely.}$$

This is the **Shannon–McMillan–Breiman theorem**. Its proof is genuinely harder — it rests on the Birkhoff ergodic theorem together with a martingale-convergence argument for the conditional densities — and is beyond the scope of this chapter. We use it only to state results in their natural generality; every proof given here is carried out in the i.i.d. case, where the weak law suffices.
:::

:::intuition
Toss a biased coin a million times. You cannot predict the sequence, but you *can* predict its cost: almost every outcome you will ever see takes about the same number of bits to write down, namely $h$ per toss.

Strings that are much cheaper (all heads) or much more expensive exist, but their total probability is negligible. Compression is the art of budgeting for the ordinary strings and merely coping with the rest.
:::

:::example[Sample rate of a specific string]
A memoryless binary source has $p(1) = 0.8$ and $p(0) = 0.2$. Compute $H(X)$ and the sample information rate of the particular string $x^{10} = 1111011110$.
:::

:::solution
The entropy is

$$H = -0.8\log 0.8 - 0.2\log 0.2 = 0.8(0.3219) + 0.2(2.3219) = 0.7219 \text{ bits/symbol.}$$

The string has eight 1s and two 0s, so

$$p(x^{10}) = 0.8^{8}\,0.2^{2} = (0.16777)(0.04) = 6.711\times10^{-3},$$

and its sample information rate is

$$-\frac{1}{10}\log_2\bigl(6.711\times10^{-3}\bigr) = \frac{7.219}{10} = 0.7219 \text{ bits/symbol.}$$

**Sanity check:** the string has exactly the expected composition (80% ones), so its rate lands exactly on $H$. A string with five 1s and five 0s would give $-\frac1{10}\log(0.8^5 0.2^5) = 1.1610$ bits/symbol, far above $H$ — atypical, and correspondingly improbable.
:::

:::pitfall[The AEP is not "all sequences are equally likely"]
The AEP says that the *logarithm* of the probability, divided by $n$, concentrates. It does not say probabilities are equal: two typical strings of length $1000$ may have probabilities differing by a factor of $2^{20}$ and still both be typical, because $20/1000$ is small. "Equipartition" is a statement about bits per symbol, not about total probability.
:::

## The Typical Set and How Big It Is {#typical-set}

<!-- section: typical-set -->

The AEP is a statement about a limit in probability. To use it we convert it into a statement about a *set* — the strings whose rate is close to $h$.

:::definition[Typical set]{#typical-set-def}
For $\varepsilon > 0$ and $n \ge 1$, the **typical set** $A_\varepsilon^{(n)} \subseteq \mathcal{X}^n$ consists of the strings whose sample information rate is within $\varepsilon$ of the entropy:

$$A_\varepsilon^{(n)} = \Bigl\{ x^n \in \mathcal{X}^n : \bigl| -\tfrac1n \log p(x^n) - H \bigr| \le \varepsilon \Bigr\},$$

equivalently the strings with

$$2^{-n(H+\varepsilon)} \;\le\; p(x^n) \;\le\; 2^{-n(H-\varepsilon)} .$$
:::

The two displays say the same thing; the second is the form used in every proof, so it is worth memorising. Typicality is defined *relative to a source*: a string is not typical or atypical in itself, only with respect to a distribution.

:::theorem[Properties of the typical set]{#typical-set-properties}
Let $X_1,\dots,X_n$ be i.i.d. $\sim p$ with entropy $H$. For every $\varepsilon>0$:

1. **Probability.** $\Pr\bigl(X^n \in A_\varepsilon^{(n)}\bigr) > 1-\varepsilon$ for all sufficiently large $n$.
2. **Upper bound on size.** $\bigl|A_\varepsilon^{(n)}\bigr| \le 2^{n(H+\varepsilon)}$ for every $n$.
3. **Lower bound on size.** $\bigl|A_\varepsilon^{(n)}\bigr| \ge (1-\varepsilon)\,2^{n(H-\varepsilon)}$ for all sufficiently large $n$.
:::

:::proof
**(1)** is a restatement of the AEP: convergence in probability of $-\frac1n\log p(X^n)$ to $H$ means precisely that the probability of the event $\bigl|-\frac1n\log p(X^n) - H\bigr| \le \varepsilon$ exceeds $1-\varepsilon$ once $n$ is large enough.

**(2)** Every typical string has probability at least $2^{-n(H+\varepsilon)}$, and probabilities of disjoint outcomes cannot sum past one:

$$1 \;\ge\; \sum_{x^n \in A_\varepsilon^{(n)}} p(x^n) \;\ge\; \sum_{x^n \in A_\varepsilon^{(n)}} 2^{-n(H+\varepsilon)} \;=\; \bigl|A_\varepsilon^{(n)}\bigr|\,2^{-n(H+\varepsilon)} .$$

Rearranging gives the bound, and note that it holds for *every* $n$, not only for large $n$.

**(3)** Run the same computation from the other side. For $n$ large enough that (1) holds,

$$1-\varepsilon \;<\; \Pr\bigl(A_\varepsilon^{(n)}\bigr) \;=\; \sum_{x^n \in A_\varepsilon^{(n)}} p(x^n) \;\le\; \bigl|A_\varepsilon^{(n)}\bigr|\, 2^{-n(H-\varepsilon)},$$

using the upper bound $p(x^n) \le 2^{-n(H-\varepsilon)}$ valid on the typical set. Rearranging gives (3).
:::

Clauses (2) and (3) pin the size of the typical set between $(1-\varepsilon)2^{n(H-\varepsilon)}$ and $2^{n(H+\varepsilon)}$: to first order in the exponent, $|A_\varepsilon^{(n)}| \approx 2^{nH}$. The whole space has $|\mathcal{X}|^n = 2^{n\log|\mathcal{X}|}$ strings, and $H \le \log|\mathcal{X}|$ with equality only for the uniform distribution. So unless the source is uniform, the typical set is an *exponentially vanishing fraction* of the space that nevertheless captures all but $\varepsilon$ of the probability.

:::intuition
Picture the space of all length-$n$ strings as a vast warehouse. The typical set is one small room inside it. Almost every string the source ever emits is found in that room, and the room holds about $2^{nH}$ objects, so a shelf label of $nH$ bits is enough to name any of them.

The rest of the warehouse is enormous but effectively empty: you may ignore it at the cost of an error probability $\varepsilon$ you choose in advance.
:::

:::example[The typical set of a biased coin]
For the source $p(1)=0.9$, $p(0)=0.1$ with $n=100$ and $\varepsilon=0.05$, estimate the size of the typical set and its share of the $2^{100}$ binary strings.
:::

:::solution
The entropy is

$$H = -0.9\log 0.9 - 0.1\log 0.1 = 0.9(0.152) + 0.1(3.322) = 0.469 \text{ bits/symbol.}$$

By clauses (2) and (3), the size lies between roughly $2^{100(0.469-0.05)} = 2^{41.9}$ and $2^{100(0.469+0.05)} = 2^{51.9}$; the natural estimate is $2^{nH} = 2^{46.9} \approx 1.3\times10^{14}$.

The fraction of the space is therefore about

$$\frac{2^{46.9}}{2^{100}} = 2^{-53.1} \approx 1.1\times 10^{-16}.$$

**Sanity check by direct counting.** Typical strings are those with about $90$ ones; the number with exactly $90$ ones is $\binom{100}{90} \approx 1.73\times10^{13} = 2^{44.0}$, the same order as $2^{46.9}$ once the neighbouring compositions (roughly $86$ to $94$ ones) admitted by the $\varepsilon$-window are added. The two computations agree, as they must: the AEP for a binary source is the law of large numbers for the number of ones.
:::

:::theorem[No smaller high-probability set exists]{#smallest-set}
Fix $\delta < \tfrac12$ and let $B_n \subseteq \mathcal{X}^n$ be *any* sequence of sets with $\Pr(X^n \in B_n) \ge 1-\delta$. Then for every $\varepsilon > 0$ and all sufficiently large $n$,

$$\frac1n \log |B_n| \;>\; H - \varepsilon .$$

No high-probability set can be essentially smaller than the typical set: about $2^{nH}$ strings are needed, whatever shape the set is given.
:::

:::proof
Write $A = A_{\varepsilon/2}^{(n)}$. Since $\Pr(B_n) \ge 1-\delta$ and $\Pr(A) \ge 1-\varepsilon'$ for any prescribed $\varepsilon'$ once $n$ is large, the union bound gives

$$\Pr(B_n \cap A) \;\ge\; 1 - \delta - \varepsilon' .$$

Every string in $A$ has $p(x^n) \le 2^{-n(H-\varepsilon/2)}$, so

$$1-\delta-\varepsilon' \;\le\; \Pr(B_n \cap A) \;=\!\!\sum_{x^n \in B_n\cap A}\!\! p(x^n) \;\le\; |B_n \cap A|\,2^{-n(H-\varepsilon/2)} \;\le\; |B_n|\,2^{-n(H-\varepsilon/2)} .$$

Hence $|B_n| \ge (1-\delta-\varepsilon')\,2^{n(H-\varepsilon/2)}$ and

$$\frac1n\log|B_n| \;\ge\; H - \frac{\varepsilon}{2} + \frac{\log(1-\delta-\varepsilon')}{n} \;>\; H - \varepsilon$$

for $n$ large, because $\delta < \frac12$ lets us choose $\varepsilon'$ with $1-\delta-\varepsilon' > 0$, making the last term vanish.
:::

This theorem is the reason the typical set is the *right* object and not merely a convenient one. One might hope to beat it by taking the $2^{nR}$ most probable strings instead, with $R<H$; the theorem says any such set has probability tending to zero.

:::pitfall[The most probable string is usually atypical]
For $p(1)=0.9$ the single most probable string of length $n$ is $111\cdots1$, with probability $0.9^n = 2^{-0.152n}$. Its sample information rate is $0.152$, nowhere near $H = 0.469$, so it is *not* typical for small $\varepsilon$. The typical set is not the set of likely strings; it is the set of strings of likely *composition*. High-probability sets are assembled from many mid-probability strings, not from the few champions.
:::

## Compressing with the Typical Set {#applications}

<!-- section: applications -->

We can now build a compressor. It is crude — a lookup table of astronomical size — but it proves that the entropy rate is achievable, and every later algorithm is an attempt to obtain the same rate with feasible resources.

:::recipe[Typical-set block code]{#typical-set-code}
Fix $\varepsilon>0$ and a block length $n$. Split $\mathcal{X}^n$ into the typical set $A_\varepsilon^{(n)}$ and its complement, and encode a block $x^n$ as follows.

1. If $x^n \in A_\varepsilon^{(n)}$: emit the flag bit $0$, followed by the index of $x^n$ in a fixed enumeration of $A_\varepsilon^{(n)}$, written in $\lceil n(H+\varepsilon)\rceil$ bits.
2. Otherwise: emit the flag bit $1$, followed by the index of $x^n$ in $\mathcal{X}^n$, written in $\lceil n\log|\mathcal{X}|\rceil$ bits.

The decoder reads the flag bit and looks the index up in the corresponding table, so the code is lossless — every string is recovered exactly.
:::

The flag bit is what makes the two branches decodable, and it is the price of admitting that atypical strings exist. Note that this scheme never errs: $\varepsilon$ appears in the *length*, not in a failure probability.

:::theorem[Expected length of the typical-set code]{#typical-code-length}
Let $\ell(X^n)$ be the length in bits produced by the typical-set block code. For every $\varepsilon'>0$ there is an $n_0$ such that for all $n > n_0$,

$$E\!\left[\frac{1}{n}\,\ell(X^n)\right] \;\le\; H + \varepsilon' .$$
:::

:::proof
Split the expectation over the two branches. On the typical set the length is at most $n(H+\varepsilon)+2$ (one flag bit and at most one bit lost to the ceiling); on the complement it is at most $n\log|\mathcal{X}| + 2$. Therefore

$$E[\ell(X^n)] \;\le\; \Pr\!\bigl(A_\varepsilon^{(n)}\bigr)\bigl(n(H+\varepsilon)+2\bigr) + \Pr\!\bigl(\overline{A_\varepsilon^{(n)}}\bigr)\bigl(n\log|\mathcal{X}|+2\bigr).$$

Bounding the first probability by $1$ and, for large $n$, the second by $\varepsilon$,

$$E\!\left[\frac1n \ell(X^n)\right] \;\le\; H + \varepsilon + \varepsilon\log|\mathcal{X}| + \frac2n \;=\; H + \varepsilon\bigl(1+\log|\mathcal{X}|\bigr) + \frac2n .$$

Given $\varepsilon'>0$, choose $\varepsilon = \varepsilon'/\bigl(2(1+\log|\mathcal{X}|)\bigr)$ and then $n_0 > 4/\varepsilon'$; for $n>n_0$ the right-hand side is at most $H+\varepsilon'$.
:::

:::corollary[Entropy is an achievable description length]{#entropy-achievable}
For any source satisfying the AEP with entropy rate $h$, and any $\varepsilon>0$, there exist lossless codes with expected description length at most $h+\varepsilon$ bits per symbol for all sufficiently large block lengths.
:::

The corollary is the achievability half of the source coding theorem, obtained before the theorem is even stated. What the next part adds is precision about *what kind* of code is allowed, and a matching converse.

:::intuition
The compressor is a phone book. All the ordinary strings are listed in it, and to send one you send its page-and-line number. The occasional bizarre string is not in the book, so you prefix it with "not in the book" and spell it out in full.

Spelling out is expensive, but you do it so rarely that on average it costs nothing.
:::

:::example[Rate of a typical-set code for a video frame]
A residual video frame of $1920\times1080$ pixels is modelled as an i.i.d. source over a $256$-level alphabet with $H = 0.8$ bits per pixel. Compare the raw size, the typical branch, and the average overhead of the atypical branch if $\Pr(\text{atypical}) = 10^{-3}$.
:::

:::solution
There are $n = 1920 \times 1080 = 2{,}073{,}600$ pixels.

*Raw.* At $\log 256 = 8$ bits per pixel: $8n = 16{,}588{,}800$ bits $\approx 2.07$ MB.

*Typical branch.* $n(H+\varepsilon)$ with $\varepsilon$ negligible at this $n$: $0.8n = 1{,}658{,}880$ bits $\approx 207$ kB — a ratio of $8/0.8 = 10{:}1$.

*Atypical branch.* It costs $8n$ bits but occurs with probability $10^{-3}$, contributing $10^{-3}\times 8 = 0.008$ bits per pixel to the average — one percent of the $0.8$-bit budget.

Average rate: $0.999(0.8) + 0.001(8) = 0.8072$ bits per pixel.

**Sanity check:** the average exceeds $H$ by $0.0072$ bits per pixel, consistent with the $\varepsilon(1+\log|\mathcal{X}|)$ overhead term in the proof above with $\varepsilon = 10^{-3}$, namely $10^{-3}(1+8) = 0.009$ — the right order. The typical-set bound is not a fiction; it is what the arithmetic actually gives.
:::

:::remark[Why this code is never built]
The table $A_\varepsilon^{(n)}$ has about $2^{nH}$ entries. For the frame above that is $2^{1658880}$ entries — more than the number of atoms in any number of universes. The typical-set code is an *existence* argument. The rest of this chapter is about obtaining the same rate with an algorithm that runs in linear time and constant memory; remarkably, this turns out to be possible.
:::

## Common Mistakes

- **Thinking every sequence has probability exactly $2^{-nh}$.** Only typical ones have probability close to that *on the exponential scale*, and even they vary by subexponential factors. Atypical strings can be far more or far less likely.
- **Confusing the size of the typical set with the size of the support.** The support is usually all of $\mathcal{X}^n$; the typical set is the exponentially smaller subset of size about $2^{nH}$.
- **Dropping the ergodicity or stationarity hypothesis.** Without it the entropy rate may not exist, and the concentration in the AEP can fail outright.
- **Treating the AEP as exact at finite $n$.** It is asymptotic. For short blocks the atypical branch is not negligible and one needs explicit finite-$n$ bounds (Chebyshev, or a Chernoff bound).
- **Confusing the AEP with the central limit theorem.** Both concern $\frac1n\sum_i(-\log p(X_i))$, but the AEP is a law of large numbers (the mean converges); the CLT describes the $\sqrt n$-scale fluctuations around it, which govern finite-blocklength corrections.
- **Assuming typicality is a property of a string.** It is a property of a string *and* a distribution. The all-ones string is typical for $p(1)=1-1/n$ and wildly atypical for a fair coin.

Shannon's source coding theorem — the *noiseless coding theorem* — is the first of the two pillars of information theory. It converts the counting facts of the previous part into a sharp statement about which compression schemes can exist. Its content is that a single number, the entropy rate, is simultaneously an upper and a lower bound on the achievable rate, so that the compressibility of a source is not a matter of ingenuity but of arithmetic.

## What the Theorem Says {#statement}

<!-- section: statement -->

To state the theorem we must first say precisely what a code is and what its rate means. Vagueness here is what makes the theorem sound paradoxical ("surely a clever enough algorithm...").

:::definition[Fixed-rate block code and its rate]{#block-code-source}
A **block code of length $n$ and rate $R$** for a source with alphabet $\mathcal{X}$ is a pair of maps

$$f_n : \mathcal{X}^n \to \{1,2,\dots,2^{\lceil nR\rceil}\}, \qquad g_n : \{1,2,\dots,2^{\lceil nR\rceil}\} \to \mathcal{X}^n ,$$

the encoder and the decoder. Its **error probability** is

$$P_e^{(n)} = \Pr\bigl(g_n(f_n(X^n)) \neq X^n\bigr).$$

The rate $R$ is the number of bits transmitted per source symbol.
:::

The encoder may be any function whatsoever — no structure, locality or computability is required — so a converse proved for this class applies to every conceivable algorithm. That generosity is what makes the negative half of the theorem meaningful.

:::definition[Achievable rate]{#achievable-rate-source}
A rate $R$ is **achievable** for the source if there exists a sequence of block codes of rate $R$ with $P_e^{(n)} \to 0$ as $n\to\infty$.
:::

:::theorem[Shannon's source coding theorem]{#source-coding-theorem}
Let $\{X_i\}$ be a stationary ergodic source with entropy rate $h$.

- **Achievability.** Every rate $R > h$ is achievable: there are block codes of rate $R$ with $P_e^{(n)} \to 0$.
- **Converse.** No rate $R < h$ is achievable. In fact every sequence of block codes of rate $R < h$ has $P_e^{(n)} \to 1$.

Consequently the infimum of achievable rates equals $h$ exactly.
:::

The two halves squeeze the answer from opposite sides. Achievability is a construction; the converse is a counting argument. Neither alone would be worth much: without the converse, $h$ would merely be a rate someone once attained; without achievability, it would be a bound nobody could reach.

:::remark[Where the error probability went]
The typical-set code of the previous part was lossless with a variable length; this theorem concerns fixed-length codes that may fail. The two formulations are equivalent in the limit, and we will meet both: fixed length with vanishing error here, variable length with zero error in the discussion of Kraft's inequality. What cannot be had is fixed length, zero error, and rate below $\log|\mathcal{X}|$ — that combination is forbidden by the pigeonhole principle at every $n$.
:::

:::intuition
Entropy is the irreducible size of the data, in the way a suitcase has an irreducible volume. Good compression gets close to it; nothing gets past it, however the packing is organised.

If someone advertises a compressor that beats the entropy rate of your source on average and never errs, they are advertising a bijection from a set into a strictly smaller set.
:::

:::example[Reading the theorem off a four-letter source]
A memoryless source emits $a,b,c,d$ with probabilities $0.5, 0.25, 0.125, 0.125$. What does the theorem promise, and what does it forbid?
:::

:::solution
The entropy is

$$H = 0.5(1) + 0.25(2) + 0.125(3) + 0.125(3) = 1.75 \text{ bits/symbol,}$$

using $-\log 0.5 = 1$, $-\log 0.25 = 2$, $-\log 0.125 = 3$.

*Promised.* Any rate above $1.75$, say $1.76$, is achievable: for large $n$ there are codes using $1.76n$ bits per block whose failure probability is as small as desired. A file of $10^{6}$ symbols fits in about $1.75$ Mbit.

*Forbidden.* No scheme of rate $1.74$ can work: its error probability tends to $1$, not merely away from $0$.

*Baseline.* The naive fixed-length code uses $\log 4 = 2$ bits per symbol, so the available saving is $2 - 1.75 = 0.25$ bits per symbol, a $12.5\%$ reduction.

**Sanity check:** the probabilities are all powers of $1/2$, so a symbol code should hit $1.75$ exactly. Assigning $a \mapsto 0$, $b \mapsto 10$, $c \mapsto 110$, $d \mapsto 111$ gives expected length $0.5(1)+0.25(2)+0.125(3)+0.125(3) = 1.75$ — the entropy on the nose, with no block coding at all. Dyadic sources are the easy case; the theorem's asymptotics are what rescue the general one.
:::

## Achievability: Codes That Reach the Entropy {#achievability}

<!-- section: achievability -->

The achievability half is the typical-set code of the previous part, adapted from variable length to fixed length. The adaptation is where the error probability enters: with a fixed budget of $nR$ bits and no flag bit to spend, atypical strings cannot be encoded at all, so they are declared errors.

:::theorem[Achievability]{#achievability-theorem}
Let the source be i.i.d. with entropy $H$, and let $R > H$. Then there is a sequence of block codes of rate $R$ with $P_e^{(n)} \to 0$. Moreover the error probability can be made to decay exponentially in $n$.
:::

:::proof
Choose $\varepsilon = (R-H)/2 > 0$, so that $H + \varepsilon < R$. Let $A_\varepsilon^{(n)}$ be the typical set. By clause (2) of the typical-set properties,

$$\bigl|A_\varepsilon^{(n)}\bigr| \;\le\; 2^{n(H+\varepsilon)} \;<\; 2^{nR} \;\le\; 2^{\lceil nR\rceil},$$

so for every $n$ there are strictly more codewords available than typical strings. Define $f_n$ to map the typical strings injectively onto distinct indices (possible by the count just made) and every atypical string to index $1$; define $g_n$ to invert $f_n$ on the image of the typical set.

Every typical string is then reconstructed exactly, so

$$P_e^{(n)} \;\le\; \Pr\bigl(X^n \notin A_\varepsilon^{(n)}\bigr) \;\longrightarrow\; 0$$

by clause (1). This proves achievability.

For the exponential refinement, note that $X^n \notin A_\varepsilon^{(n)}$ is the event that the average of the i.i.d. bounded variables $Y_i = -\log p(X_i)$ deviates from its mean by at least $\varepsilon$. Hoeffding's inequality bounds this probability by $2\exp(-2n\varepsilon^2/c^2)$, where $c$ is the range of $Y_i$; hence $P_e^{(n)}$ decays exponentially in $n$, at a rate controlled by $\varepsilon = (R-H)/2$.
:::

:::corollary[The infimum of achievable rates is at most the entropy]{#achievable-inf}
Every $R>h$ is achievable, so $\inf\{R : R \text{ achievable}\} \le h$.
:::

:::intuition
You do not need a codeword for every string, only for the strings that actually show up. Reserve one index for "something weird happened" and spend the rest of the codebook on ordinary strings.

Since there are only about $2^{nH}$ ordinary strings, a codebook of $2^{nR}$ entries with $R>H$ is roomy — exponentially roomy, which is why the failure probability collapses so fast.
:::

:::example[Sizing a codebook]
A source has $H = 2.3$ bits/symbol on an eight-letter alphabet. For $n = 1000$ and $R = 2.4$, how many typical strings are there, how many codewords, and how much slack is there?
:::

:::solution
With $\varepsilon = (R-H)/2 = 0.05$, the typical set has at most $2^{n(H+\varepsilon)} = 2^{1000(2.35)} = 2^{2350}$ members.

The codebook has $2^{nR} = 2^{2400}$ entries.

The slack is a factor of $2^{2400-2350} = 2^{50} \approx 1.1\times 10^{15}$: the codebook is a quadrillion times larger than it needs to be.

**Sanity check:** compare with the raw alternative. A fixed-length code with no modelling needs $\log 8 = 3$ bits per symbol, i.e. $2^{3000}$ codewords. The typical-set code uses $2^{2400}$, saving $600$ bits per block — precisely $n(3 - 2.4)$. The saving comes from the gap between $\log|\mathcal{X}| = 3$ and $H = 2.3$, which is the source's redundancy.
:::

:::pitfall[Achievability does not make the code practical]
The proof exhibits a code by listing a set of size $2^{2350}$. It says nothing about computing $f_n$ without that list. Every practical coder in this chapter — Huffman, arithmetic, Lempel–Ziv — exists because the achievability proof is useless as an implementation, and each attains the same asymptotic rate with resources that fit in a machine.
:::

## The Converse: Why Entropy Cannot Be Beaten {#converse}

<!-- section: converse -->

The converse says that if you insist on a rate below $h$, the decoder must fail, and fail almost always. It is proved by counting: a codebook of $2^{nR}$ entries cannot address $2^{nH}$ typical strings when $R<H$.

:::lemma[Fano's inequality]{#fano}
Let $X$ be a random variable on a finite set $\mathcal{X}$, let $Y$ be any other random variable, and let $\hat X = g(Y)$ be an estimate of $X$ from $Y$. Put $P_e = \Pr(\hat X \neq X)$. Then

$$H(P_e) + P_e \log\bigl(|\mathcal{X}|-1\bigr) \;\ge\; H(X\mid Y),$$

where $H(P_e) = -P_e\log P_e - (1-P_e)\log(1-P_e)$ is the binary entropy. In particular

$$P_e \;\ge\; \frac{H(X\mid Y) - 1}{\log|\mathcal{X}|} .$$
:::

:::proof
Let $E = \mathbf{1}\{\hat X \neq X\}$ be the error indicator. Expand $H(E, X \mid Y)$ by the chain rule in two ways:

$$H(E,X\mid Y) = H(X\mid Y) + H(E\mid X,Y) = H(E\mid Y) + H(X\mid E,Y).$$

Here $H(E\mid X,Y) = 0$, because $\hat X$ is a function of $Y$, so knowing $X$ and $Y$ determines $E$. Also $H(E\mid Y) \le H(E) = H(P_e)$, since conditioning cannot increase entropy. Finally

$$H(X\mid E,Y) = \Pr(E=0)\,H(X \mid Y, E=0) + \Pr(E=1)\,H(X\mid Y, E=1) \le 0 + P_e \log\bigl(|\mathcal{X}|-1\bigr),$$

because given $E=0$ we have $X = g(Y)$ exactly (zero entropy), while given $E=1$ the variable $X$ ranges over at most $|\mathcal{X}|-1$ values, whose entropy is at most $\log(|\mathcal{X}|-1)$. Combining the three bounds with the chain-rule identity gives the inequality; the weaker form follows from $H(P_e)\le 1$ and $\log(|\mathcal{X}|-1) \le \log|\mathcal{X}|$.
:::

Fano's inequality is the formal version of "if uncertainty about $X$ remains after seeing $Y$, any guess must sometimes be wrong". It is the standard engine of converses throughout information theory; here we use a sharper, purely combinatorial argument that yields $P_e \to 1$ rather than merely $P_e \not\to 0$.

:::theorem[Converse to the source coding theorem]{#converse-theorem}
Let the source be i.i.d. with entropy $H$, and let $R < H$. Then every sequence of block codes of rate $R$ satisfies $P_e^{(n)} \to 1$.
:::

:::proof
Fix such a sequence and let

$$B_n = \bigl\{ x^n \in \mathcal{X}^n : g_n(f_n(x^n)) = x^n \bigr\}$$

be the set of strings the code reconstructs correctly. Since $g_n$ is a function of an index taking at most $2^{\lceil nR\rceil}$ values, and distinct elements of $B_n$ must receive distinct indices, we have the crucial count

$$|B_n| \;\le\; 2^{\lceil nR\rceil} \;\le\; 2^{nR+1}.$$

Now choose $\varepsilon>0$ with $\varepsilon < (H-R)/2$ and split the success probability across the typical set:

$$1 - P_e^{(n)} = \Pr(B_n) = \Pr\bigl(B_n \cap A_\varepsilon^{(n)}\bigr) + \Pr\bigl(B_n \cap \overline{A_\varepsilon^{(n)}}\bigr).$$

For the first term, every typical string has $p(x^n) \le 2^{-n(H-\varepsilon)}$, so

$$\Pr\bigl(B_n\cap A_\varepsilon^{(n)}\bigr) \;\le\; |B_n| \, 2^{-n(H-\varepsilon)} \;\le\; 2^{nR+1-n(H-\varepsilon)} \;=\; 2\cdot 2^{-n(H-R-\varepsilon)} .$$

Since $H - R - \varepsilon > \varepsilon > 0$, this tends to $0$ exponentially fast. The second term is at most $\Pr\bigl(\overline{A_\varepsilon^{(n)}}\bigr)$, which tends to $0$ by the AEP. Hence $1 - P_e^{(n)} \to 0$, i.e. $P_e^{(n)}\to 1$.
:::

:::corollary[Entropy is exactly the compression limit]{#rate-equals-entropy}
Combining achievability and the converse, the infimum of achievable rates for an i.i.d. source equals $H(X)$; for a stationary ergodic source it equals the entropy rate $h$.
:::

:::intuition
A codebook with $2^{nR}$ entries has $2^{nR}$ pigeonholes. There are $2^{nH}$ typical strings — the ones that actually arrive. If $R<H$, almost every arriving string shares its pigeonhole with others, and the decoder, seeing only the pigeonhole, cannot tell which one was sent.

The error tends to $1$ rather than to some middling value because the mismatch is *exponential*: the shortfall is a factor $2^{n(H-R)}$, so the fraction of strings with a private pigeonhole is exponentially small.
:::

:::example[Auditing a compression claim]
A vendor claims a lossless compressor that maps every $1000$-bit file from a fair-coin source to at most $900$ bits. Refute it, and quantify how often it must fail.
:::

:::solution
For a fair coin $H = 1$ bit/symbol, so the claimed rate is $R = 0.9 < 1 = H$.

*Counting.* Outputs have length at most $900$, so there are at most $2^{901}-1 < 2^{901}$ distinct outputs against $2^{1000}$ equally likely inputs. At most $2^{901}$ inputs can be recovered, a fraction

$$\frac{2^{901}}{2^{1000}} = 2^{-99} \approx 1.6\times 10^{-30}.$$

*Failure rate.* The failure probability is therefore at least $1 - 2^{-99}$, indistinguishable from certainty.

**Sanity check against the theorem.** The converse predicts a success probability of at most $2\cdot 2^{-n(H-R-\varepsilon)}$ plus the atypical term, and with $H-R = 0.1$ and $n=1000$ that is about $2^{-99}$ — matching the direct count. Note also that the claim is refuted *without* the AEP: for a fair coin every string is typical, and plain pigeonhole suffices.
:::

:::pitfall[Compressing one file is not compressing a source]
It is entirely possible to map one particular $1000$-bit file to $10$ bits. What is impossible is to do so for all of them at once: any injective map into shorter strings must lengthen at least as many files as it shortens. Claims of universal compression always trade on this confusion between a single input and a distribution over inputs.
:::

## Common Mistakes

- **Reading the theorem as a statement about single messages.** It is asymptotic in block length and probabilistic in the source. Individual short messages can beat $H$ or fall far short of it.
- **Confusing the source coding theorem with the channel coding theorem.** Source coding removes redundancy to approach $h$; channel coding adds redundancy to approach capacity. They are dual, not the same.
- **Using $H(X)$ for a source with memory.** The limit is the entropy *rate* $h = \lim H(X_n \mid X^{n-1})$, which can be far below the marginal entropy: English has a marginal letter entropy above $4$ bits but an entropy rate near $1.3$ bits.
- **Forgetting the vanishing-error qualifier in the achievability half.** Fixed-rate codes below $\log|\mathcal{X}|$ must sometimes fail; the theorem promises only that the failure probability tends to zero.
- **Believing the converse follows from Fano's inequality alone.** Fano gives $P_e$ bounded away from zero; the exponential counting argument is what gives $P_e \to 1$.
- **Assuming a smarter codebook could beat the count.** The converse quantifies over *all* functions $f_n$, computable or not. There is no algorithmic escape from a pigeonhole.

The theory so far speaks of blocks of length $n\to\infty$ and codebooks of astronomical size. Real compressors read a file once, symbol by symbol, and emit bits as they go. This part makes the transition: from block codes to **symbol codes**, where the combinatorial constraint is not a pigeonhole count but *Kraft's inequality*, and where the asymptotic bound $L \to H$ is replaced by the sharp finite bound $H \le L < H+1$.

## Lossless and Lossy Compression {#lossless-vs-lossy}

<!-- section: lossless-vs-lossy -->

:::definition[Lossless and lossy compression]{#lossless-lossy}
A compression scheme is a pair of maps $(\text{enc}, \text{dec})$. It is **lossless** on a set $S$ of inputs if $\text{dec}(\text{enc}(x)) = x$ for every $x\in S$ — the encoder is injective on $S$ and the decoder inverts it. It is **lossy** if the reconstruction is allowed to differ from the input, the discrepancy being measured by a distortion function $d(x,\hat x)$ whose expectation is held below a budget $D$.
:::

Lossless compression (gzip, PNG, FLAC, ZIP) is required for text, executables and scientific data, where a single flipped bit is a defect. Lossy compression (JPEG, MP3, H.264, Opus) discards information judged perceptually irrelevant and thereby escapes the entropy bound entirely — at the price of an irreversible change to the data.

The distinction is not a matter of degree: it is the difference between an injective map and a non-injective one. And injectivity alone forbids the thing amateurs most often claim.

:::theorem[No lossless code compresses everything]{#no-free-lunch}
Let $C$ be any injective map from binary strings to binary strings. Then for every $n$ and every $k \ge 1$, the fraction of strings $x$ of length $n$ with $|C(x)| \le n-k$ is less than $2^{-k+1}$.

In particular no lossless compressor can shorten even half of the $n$-bit inputs by as much as $2$ bits, and any compressor that shortens some inputs must lengthen others.
:::

:::proof
The strings of length at most $n-k$ number

$$\sum_{j=0}^{n-k} 2^{j} = 2^{n-k+1}-1 \;<\; 2^{n-k+1}.$$

Because $C$ is injective, distinct inputs of length $n$ receive distinct outputs, so at most $2^{n-k+1}-1$ of the $2^n$ inputs can have an output that short. The fraction is therefore less than $2^{n-k+1}/2^n = 2^{-k+1}$.

For the final claim, take $k=0$: the number of strings of length $< n$ is $2^n - 1 < 2^n$, so at least one string of length $n$ must map to an output of length $\ge n$. Iterating over all $n$ shows that a compressor that strictly shortens some inputs strictly lengthens others.
:::

:::intuition
Lossless compression is vacuum-packing: the suitcase shrinks, and everything is still inside when you open it. Lossy compression is deciding which souvenirs to leave behind — the case shrinks much more, and the decision is permanent.

The no-free-lunch theorem is just the observation that you cannot put $2^n$ distinct objects into fewer than $2^n$ distinct boxes. Compressors "work" because real files are not uniformly distributed over all bit strings; they are concentrated on a typical set.
:::

:::example[Quantifying the no-free-lunch bound]
Of all $1{,}000$-bit files, what fraction can a lossless compressor possibly shrink to $990$ bits or fewer? To $500$ bits or fewer?
:::

:::solution
Apply the theorem with $n = 1000$.

For $k = 10$: the fraction is less than $2^{-9} = 1/512 \approx 0.2\%$.

For $k = 500$: the fraction is less than $2^{-499} \approx 6\times10^{-151}$.

**Sanity check:** the numbers are consistent with everyday experience. gzip shrinks text by 60–70% not because the theorem is false but because text files are a vanishingly small, highly structured subset of all bit strings — exactly the typical set of a low-entropy source. Feed gzip the output of a good random number generator and the file grows by a few bytes, as the theorem requires.
:::

:::remark[The lossy analogue]
For lossy compression the entropy bound is replaced by the **rate–distortion function** $R(D) = \min I(X;\hat X)$, the minimum over all conditional distributions $p(\hat x \mid x)$ meeting $E[d(X,\hat X)] \le D$. It satisfies $R(0) = H(X)$ for discrete sources, so lossless compression is the $D=0$ endpoint of the lossy theory. Rate–distortion theory is developed in its own chapter; here we only note that all rates below $H$ are purchased with distortion.
:::

## Redundancy, Models, and the Cost of Being Wrong {#redundancy}

<!-- section: redundancy -->

Every compressor is a probability model in disguise. Given a model $q$ over strings, the ideal codelength for $x$ is $\log(1/q(x))$ bits; given a coder, the lengths it produces define an implicit model $q(x) \approx 2^{-\ell(x)}$. Compression performance is therefore entirely a question of how close the model is to the truth, and information theory measures that distance exactly.

:::definition[Redundancy]{#redundancy-def}
For a source with entropy $H$ coded at expected length $L$, the **absolute redundancy** is $L - H$ bits per symbol and the **relative redundancy** is $(L-H)/L$. For a fixed-length code over $\mathcal{X}$ the redundancy relative to the naive baseline is $\log|\mathcal{X}| - H$, the part of each symbol that a perfect model would have predicted.
:::

:::definition[Relative entropy]{#relative-entropy}
The **relative entropy** (Kullback–Leibler divergence) between mass functions $p$ and $q$ on $\mathcal{X}$ is

$$D(p\,\|\,q) = \sum_{x\in\mathcal{X}} p(x)\log\frac{p(x)}{q(x)},$$

with the conventions $0\log\frac0q = 0$ and $p\log\frac p0 = \infty$.
:::

:::lemma[Gibbs' inequality]{#gibbs}
$D(p\,\|\,q) \ge 0$ for all $p,q$, with equality if and only if $p = q$.
:::

:::proof
Let $S = \{x : p(x) > 0\}$. Using $\log t = \ln t / \ln 2$ and Jensen's inequality for the concave function $\ln$,

$$-D(p\,\|\,q) = \sum_{x\in S} p(x)\log\frac{q(x)}{p(x)} \;\le\; \log\left(\sum_{x\in S} p(x)\frac{q(x)}{p(x)}\right) = \log\left(\sum_{x \in S} q(x)\right) \le \log 1 = 0 .$$

Hence $D(p\|q)\ge 0$. Jensen's inequality is strict for the strictly concave $\log$ unless $q(x)/p(x)$ is constant on $S$, and the final inequality is strict unless $q$ puts no mass outside $S$; both hold simultaneously exactly when $q = p$.
:::

:::theorem[The cost of the wrong model]{#wrong-model}
Suppose a coder is designed for the model $q$ but the data are drawn from $p$. Using the ideal codelengths $\ell(x) = \log\frac{1}{q(x)}$, the expected length is

$$E_p[\ell(X)] = H(p) + D(p\,\|\,q) \;\ge\; H(p),$$

so the penalty for modelling $p$ as $q$ is exactly $D(p\|q)$ bits per symbol, and it is zero only if the model is right.
:::

:::proof
Expand the expectation and add and subtract $\log p(x)$:

$$E_p\!\left[\log\frac1{q(X)}\right] = \sum_x p(x)\log\frac{1}{q(x)} = \sum_x p(x)\log\frac{1}{p(x)} + \sum_x p(x)\log\frac{p(x)}{q(x)} = H(p) + D(p\,\|\,q).$$

Non-negativity of the second term is Gibbs' inequality.
:::

This is the single most useful formula in practical compression: it says that *model error is measured in bits*, on the same scale as the data, and that the two contributions — the source's own entropy and the modeller's mistake — simply add.

:::intuition
Redundancy is "what you already knew". In `aaaaaaa` the next `a` is predictable, so sending it explicitly wastes the bits you spend on it.

A compressor is a predictor with a bill attached: every time it is surprised it pays $\log(1/q)$ bits. Being surprised is unavoidable at rate $H$; being surprised *because your model is wrong* costs an extra $D(p\|q)$, and you pay it on every symbol.
:::

:::example[Paying for a mismatched model]
A binary source has $p(1) = 0.9$. A compressor assumes a fair coin, $q(1) = q(0) = 0.5$. What does it cost?
:::

:::solution
The true entropy is $H(p) = 0.469$ bits/symbol (computed earlier).

The divergence is

$$D(p\|q) = 0.9\log\frac{0.9}{0.5} + 0.1\log\frac{0.1}{0.5} = 0.9(0.8480) + 0.1(-2.3219) = 0.7632 - 0.2322 = 0.5310 \text{ bits.}$$

So the expected codelength is $0.469 + 0.531 = 1.000$ bits/symbol.

**Sanity check:** a coder built for a fair coin spends exactly $\log(1/0.5) = 1$ bit on every symbol regardless of what it sees, so its expected length is exactly $1$ — matching the theorem to the digit. The mismatched model throws away the entire $0.531$ bits per symbol of available compression.
:::

:::example[Redundancy of a source with memory]
A binary source alternates deterministically: $ababab\dots$ of length $1000$. What is its entropy rate, and how many bits does an ideal description need?
:::

:::solution
Conditioned on the previous symbol the next one is certain, so $H(X_n \mid X_{n-1}) = 0$ and the entropy rate is $h = 0$.

An explicit description needs only the starting symbol ($1$ bit) and the length ($\lceil \log 1000\rceil = 10$ bits): about $11$ bits in total.

The per-symbol rate is $11/1000 = 0.011$ bits, which tends to $0 = h$ as the string lengthens.

**Sanity check:** a memoryless model of this source would see $p(a) = p(b) = 0.5$ and report a marginal entropy of $1$ bit per symbol, demanding $1000$ bits — a factor of $90$ worse. The gap is exactly the redundancy that the first-order model captures and the zeroth-order model misses, and it is why "entropy rate, not marginal entropy" is the operative phrase.
:::

:::pitfall[Redundancy is relative to a model class]
There is no model-free measure of how compressible a particular file is (that is the province of Kolmogorov complexity, which is uncomputable). A file with zero redundancy under a memoryless model may be extremely redundant under a Markov model — the digits of $\pi$ pass every statistical test a compressor applies and are nonetheless generated by a short program.
:::

## Prefix Codes, Kraft's Inequality and the Entropy Bound {#practical}

<!-- section: practical -->

We now leave block codes behind. A **symbol code** assigns a binary string to each *letter* and codes a message by concatenation. The whole theory of such codes rests on one inequality.

:::definition[Symbol codes: non-singular, uniquely decodable, prefix]{#code-classes}
A **symbol code** is a map $C : \mathcal{X} \to \{0,1\}^{*}$; the string $C(x)$ is the codeword of $x$ and $\ell(x) = |C(x)|$ its length. The code is

- **non-singular** if $x \neq x' \Rightarrow C(x) \neq C(x')$;
- **uniquely decodable** if its extension to strings, $C(x_1\cdots x_n) = C(x_1)C(x_2)\cdots C(x_n)$, is non-singular — no two distinct messages have the same concatenation;
- **prefix-free** (or *instantaneous*) if no codeword is a prefix of another.

Every prefix code is uniquely decodable, and every uniquely decodable code is non-singular; both inclusions are strict.
:::

Prefix codes are the ones worth building: they can be decoded left to right with no lookahead, each codeword being recognised the moment its last bit arrives. Geometrically, a prefix code is a set of leaves in a binary tree, one leaf per symbol, and no leaf on the path to another.

:::theorem[Kraft's inequality]{#kraft}
If a binary prefix code has codeword lengths $\ell_1,\dots,\ell_m$, then

$$\sum_{i=1}^{m} 2^{-\ell_i} \;\le\; 1 .$$

Conversely, given positive integers $\ell_1,\dots,\ell_m$ satisfying this inequality, there exists a binary prefix code with exactly those lengths.
:::

:::proof
**Necessity.** Associate with each codeword $c$ of length $\ell$ the dyadic interval

$$I(c) = \bigl[\,0.c,\; 0.c + 2^{-\ell}\,\bigr) \subseteq [0,1),$$

where $0.c$ is the binary fraction whose digits are the bits of $c$. The interval has length exactly $2^{-\ell}$. If $c$ is not a prefix of $c'$ and $c'$ is not a prefix of $c$, then the two binary expansions differ at some position before both end, and $I(c) \cap I(c') = \varnothing$: the intervals of a prefix code are pairwise disjoint. Being disjoint subintervals of $[0,1)$, their total length is at most $1$, which is the inequality.

**Sufficiency.** Order the lengths $\ell_1 \le \ell_2 \le \cdots \le \ell_m$ and define the cumulative sums

$$w_i = \sum_{j<i} 2^{-\ell_j} \in [0,1),$$

taking $w_1 = 0$. Let $C(i)$ be the first $\ell_i$ bits of the binary expansion of $w_i$, so that $I(C(i)) = [w_i, w_i + 2^{-\ell_i})$ — this is legitimate because $w_i$ is a multiple of $2^{-\ell_i}$, each earlier term $2^{-\ell_j}$ with $\ell_j \le \ell_i$ being such a multiple. The Kraft sum being at most $1$ guarantees $w_i + 2^{-\ell_i} \le 1$, so all these intervals fit inside $[0,1)$, and by construction they are consecutive and disjoint. Disjointness of $I(C(i))$ and $I(C(j))$ forces neither codeword to be a prefix of the other, since a prefix relation would make one interval contain the other. Hence $C$ is a prefix code with the prescribed lengths.
:::

:::theorem[Kraft–McMillan: unique decodability buys nothing]{#mcmillan}
Every uniquely decodable code satisfies $\sum_i 2^{-\ell_i} \le 1$.

Consequently the set of achievable length vectors is the same for uniquely decodable codes as for prefix codes: nothing is lost by insisting on instantaneous decoding.
:::

:::proof
Let $S = \sum_{i=1}^m 2^{-\ell_i}$ and let $L = \max_i \ell_i$. For any integer $k \ge 1$, expand the $k$-th power:

$$S^k = \left(\sum_{x \in \mathcal{X}} 2^{-\ell(x)}\right)^{k} = \sum_{x_1,\dots,x_k \in \mathcal{X}} 2^{-\bigl(\ell(x_1)+\cdots+\ell(x_k)\bigr)} = \sum_{m=k}^{kL} a(m)\,2^{-m},$$

where $a(m)$ is the number of source strings of length $k$ whose concatenated encoding has exactly $m$ bits. Unique decodability means distinct length-$k$ strings give distinct binary strings, so $a(m)$ is at most the number of binary strings of length $m$, namely $2^m$. Therefore

$$S^k \;\le\; \sum_{m=k}^{kL} 2^{m}2^{-m} \;=\; kL - k + 1 \;\le\; kL .$$

Thus $S \le (kL)^{1/k}$ for every $k$. Since $(kL)^{1/k} \to 1$ as $k\to\infty$, we conclude $S \le 1$.
:::

That $k$-th power trick is due to Karush, and it is the reason the rest of the chapter can talk about prefix codes without loss of generality. Kraft's inequality now converts the coding problem into a constrained optimisation: choose lengths $\ell_i$ minimising $\sum p_i \ell_i$ subject to $\sum 2^{-\ell_i} \le 1$. Relaxing $\ell_i$ to real numbers, the solution is immediate.

:::theorem[Entropy is a lower bound on expected length]{#entropy-lower-bound}
For any uniquely decodable binary code for a source with mass function $p$, the expected codeword length $L = \sum_i p_i \ell_i$ satisfies

$$L \;\ge\; H(p),$$

with equality if and only if $p_i = 2^{-\ell_i}$ for every $i$ — that is, if and only if all probabilities are **dyadic** (integer powers of $1/2$).
:::

:::proof
By Kraft–McMillan, $c = \sum_i 2^{-\ell_i} \le 1$. Define the probability mass function $r_i = 2^{-\ell_i}/c$. Then

$$L - H(p) = \sum_i p_i \ell_i + \sum_i p_i \log p_i = \sum_i p_i \log \frac{p_i}{2^{-\ell_i}} = \sum_i p_i\log\frac{p_i}{c\,r_i} = D(p\,\|\,r) + \log\frac1c .$$

Both terms are non-negative: the first by Gibbs' inequality, the second because $c \le 1$. Hence $L \ge H(p)$. Equality requires $D(p\|r) = 0$ and $c=1$, i.e. $p = r$ and $r_i = 2^{-\ell_i}$, which is exactly $p_i = 2^{-\ell_i}$.
:::

:::definition[Shannon code]{#shannon-code}
The **Shannon code** for $p$ assigns to symbol $i$ the length

$$\ell_i = \left\lceil \log \frac{1}{p_i} \right\rceil .$$
:::

:::theorem[The fundamental bound $H \le L < H+1$]{#h-le-l}
The Shannon lengths satisfy Kraft's inequality, so a prefix code with those lengths exists, and its expected length obeys

$$H(p) \;\le\; L \;<\; H(p) + 1 .$$

Hence the optimal expected length $L^{*}$ of any prefix code satisfies the same bounds.
:::

:::proof
*Kraft.* Since $\ell_i \ge \log(1/p_i)$, we have $2^{-\ell_i} \le p_i$, so $\sum_i 2^{-\ell_i} \le \sum_i p_i = 1$. By the converse half of Kraft's inequality a prefix code with these lengths exists.

*Upper bound.* Since $\lceil t\rceil < t+1$,

$$L = \sum_i p_i\left\lceil \log\frac1{p_i}\right\rceil \;<\; \sum_i p_i\left(\log\frac1{p_i} + 1\right) = H(p) + 1 .$$

*Lower bound.* Immediate from Theorem *Entropy is a lower bound on expected length*, since the Shannon code is a prefix code.

Finally, the optimal code has $L^{*} \le L < H+1$ because the Shannon code is one candidate, and $L^{*} \ge H$ because Theorem *Entropy is a lower bound on expected length* applies to every uniquely decodable code.
:::

:::corollary[Blocking removes the overhead]{#blocking}
Apply an optimal prefix code to blocks of $n$ i.i.d. symbols. Writing $L_n^{*}$ for the optimal expected length per block,

$$H(X) \;\le\; \frac{L_n^{*}}{n} \;<\; H(X) + \frac1n ,$$

so the per-symbol length converges to the entropy. For a stationary source the same argument with $H(X_1,\dots,X_n)$ in place of $nH(X)$ gives $L_n^{*}/n \to h$.
:::

:::proof
The block $X^n$ is a single random variable over the alphabet $\mathcal{X}^n$ with entropy $H(X_1,\dots,X_n) = nH(X)$ by independence. Applying the theorem to it gives $nH(X) \le L_n^{*} < nH(X)+1$; dividing by $n$ gives the claim. In the stationary case divide $H(X_1,\dots,X_n) \le L_n^{*} < H(X_1,\dots,X_n)+1$ by $n$ and use the definition of the entropy rate.
:::

:::intuition
Kraft's inequality is a budget. Every codeword of length $\ell$ costs $2^{-\ell}$ of a total budget of $1$: short codewords are expensive, long ones cheap. Spending the whole budget optimally means buying a codeword of length $\log(1/p_i)$ for symbol $i$ — the more likely the symbol, the more you are willing to pay for a short name.

The "$+1$" in $L < H+1$ is the rounding loss: codeword lengths are integers, but $\log(1/p_i)$ generally is not. Coding blocks of $n$ symbols amortises one rounding error over $n$ symbols, which is why the overhead is $1/n$.
:::

:::example[Kraft: which length vectors are legal?]
Decide whether a binary prefix code exists with lengths (a) $\{1,2,3,3\}$, (b) $\{1,2,2,3\}$, (c) $\{2,2,2,2,2\}$.
:::

:::solution
(a) $2^{-1}+2^{-2}+2^{-3}+2^{-3} = 0.5+0.25+0.125+0.125 = 1$. Legal, and the budget is exactly exhausted — the code is *complete* (its tree has no unused leaves). Example: $0,10,110,111$.

(b) $0.5 + 0.25+0.25+0.125 = 1.125 > 1$. Illegal: no prefix code, and by Kraft–McMillan not even a uniquely decodable one.

(c) $5 \times 2^{-2} = 1.25 > 1$. Illegal — with $2$-bit codewords there are only $4$ leaves available for $5$ symbols.

**Sanity check:** in (c), replacing one length by $3$ gives $4(0.25) + 0.125 = 1.125$, still illegal; lengths $\{2,2,2,3,3\}$ give $0.75+0.25 = 1$, legal. The budget interpretation predicts exactly this: five symbols need at least $\lceil\log 5\rceil = 3$ bits in the worst case.
:::

|---|---|---|---|
| $a$ | $0.45$ | $1.152$ | $2$ |
| $b$ | $0.30$ | $1.737$ | $2$ |
| $c$ | $0.15$ | $2.737$ | $3$ |
| $d$ | $0.10$ | $3.322$ | $4$ |

Expected length: $L = 0.45(2)+0.30(2)+0.15(3)+0.10(4) = 0.9+0.6+0.45+0.4 = 2.35$ bits.

Entropy: $H = 0.45(1.152)+0.30(1.737)+0.15(2.737)+0.10(3.322) = 0.518+0.521+0.411+0.332 = 1.782$ bits.

**Sanity check:** $1.782 \le 2.35 < 2.782$ ✓ — the bound holds, though with $0.57$ bits of slack. The Kraft sum is well under $1$, which signals waste: the code is incomplete, so some codeword could be shortened. Huffman, in the next part, will find $L = 1.85$ for this same distribution, and no prefix code does better.
:::

:::pitfall[$L < H+1$ does not mean "within one bit of optimal"]
The bound compares $L$ to the *entropy*, not to the best code. A code can satisfy $L<H+1$ and still be beaten by another code, as the example above shows ($2.35$ versus Huffman's $1.85$). Only the Huffman code is guaranteed to be optimal, and even it can sit almost a full bit above $H$ when one symbol is very probable.
:::

## Common Mistakes

- **Expecting a compressor to shrink random or already-compressed data.** The no-free-lunch theorem forbids it; the output of gzip run twice is slightly larger than run once.
- **Confusing non-singular with uniquely decodable.** $\{0,1,01\}$ is non-singular but not uniquely decodable: `01` could be one symbol or two.
- **Believing unique decodability allows shorter codes than the prefix property.** Kraft–McMillan says the achievable length vectors are identical; instantaneous decoding is free.
- **Reading Kraft's inequality as a statement about a particular code.** It constrains the *multiset of lengths*. Any length vector satisfying it can be realised, and no code can violate it.
- **Ignoring model cost for small files.** The $D(p\|q)$ penalty assumes a known model; if the model must be transmitted, its description length is charged to the file, which is why compression shines on large inputs.
- **Comparing $L$ against $\log|\mathcal{X}|$ instead of $H$.** The naive baseline measures the saving; the entropy measures how much saving was left on the table.

Kraft's inequality tells us which length vectors are legal; the Shannon code shows that a legal vector within one bit of the entropy always exists. It does not tell us the *best* legal vector. That problem — minimise $\sum_i p_i\ell_i$ over all prefix codes — was solved in 1952 by David Huffman, then a graduate student who took it as a term-paper assignment after his professor, Robert Fano, mentioned that nobody knew the answer. The algorithm is three lines long, runs in $O(m\log m)$ time, and is provably optimal.

## Huffman's Algorithm {#algorithm}

<!-- section: algorithm -->

The idea is to build the code tree from the leaves upward. The two rarest symbols will end up deepest in the tree, so we decide their relationship first and then forget that they were ever separate.

:::recipe[Huffman's algorithm]{#huffman-algorithm}
Input: probabilities $p_1,\dots,p_m$ over the symbols of $\mathcal{X}$.

1. Create one leaf node per symbol, weighted by its probability, and place all $m$ nodes in a priority queue.
2. While more than one node remains: remove the two nodes of smallest weight, create a new internal node whose weight is their sum, and attach the two removed nodes as its children.
3. The last remaining node is the root. Read each symbol's codeword off the path from the root to its leaf, writing $0$ for a left branch and $1$ for a right branch.
:::

Each merge reduces the number of nodes by one, so the loop runs $m-1$ times; with a binary heap each iteration costs $O(\log m)$ and the total is $O(m\log m)$. If the probabilities arrive already sorted, two queues (one of leaves, one of merged nodes) give $O(m)$.

:::proposition[Huffman codes are prefix-free and complete]{#huffman-prefix}
The code produced by Huffman's algorithm is prefix-free, and its Kraft sum is exactly $1$.
:::

:::proof
Symbols sit only at leaves, and no leaf lies on the root-to-leaf path of another leaf, so no codeword is a prefix of another: the code is prefix-free.

For completeness, note that every internal node created in step 2 has exactly two children, so the tree is *full*. In a full binary tree the leaf depths satisfy $\sum_{\text{leaves}} 2^{-\text{depth}} = 1$, which is proved by induction on the number of internal nodes: a single leaf at depth $0$ gives $2^{0}=1$, and replacing a leaf at depth $d$ by an internal node with two children at depth $d+1$ replaces $2^{-d}$ by $2\cdot 2^{-(d+1)} = 2^{-d}$, leaving the sum unchanged.
:::

A full tree means no wasted budget: unlike the Shannon code of the previous part, whose Kraft sum was $0.6875$, a Huffman code spends every bit of its allowance.

:::intuition
Think of the probabilities as weights and each merge as tying two of them together with a string. The two lightest get tied first, so they hang lowest; heavy symbols stay near the top and get short codewords.

The key insight — and the reason greed works here — is that once two symbols are the rarest, *nothing later in the construction can improve on making them siblings*. Their combined weight is all that matters afterwards.
:::

:::example[Huffman code for a dyadic source]
Build a Huffman code for $A{:}0.5$, $B{:}0.25$, $C{:}0.125$, $D{:}0.125$.
:::

:::solution
*Merge 1.* The two smallest are $C$ and $D$ ($0.125$ each). Merge into node $E$ with weight $0.25$. Queue: $A{:}0.5,\ B{:}0.25,\ E{:}0.25$.

*Merge 2.* The two smallest are $B$ and $E$ ($0.25$ each; ties broken arbitrarily). Merge into $F$ with weight $0.5$. Queue: $A{:}0.5,\ F{:}0.5$.

*Merge 3.* Merge $A$ and $F$ into the root, weight $1.0$.

Reading the paths ($0$ = left, $1$ = right, with $A$ on the left of the root): $A = 0$, $B = 10$, $C = 110$, $D = 111$.

Expected length: $L = 0.5(1) + 0.25(2) + 0.125(3) + 0.125(3) = 1.75$ bits.

**Sanity check.** Prefix-free: $0$ is not a prefix of $10, 110, 111$, and $10$ is not a prefix of $110$ or $111$ ✓. Kraft sum: $\tfrac12 + \tfrac14 + \tfrac18 + \tfrac18 = 1$ ✓, so the tree is full. Entropy: $H = 1.75$ bits, so $L = H$ exactly — as it must be, since all probabilities are dyadic.
:::

:::example[Huffman code for a non-dyadic source]
Build a Huffman code for $p = (0.45, 0.30, 0.15, 0.10)$ — the distribution for which the Shannon code gave $L = 2.35$ — and compare.
:::

:::solution
*Merge 1.* Smallest two: $0.15$ and $0.10$ $\to$ node $u$, weight $0.25$. Queue: $0.45,\ 0.30,\ u{:}0.25$.

*Merge 2.* Smallest two: $0.30$ and $u{:}0.25$ $\to$ node $v$, weight $0.55$. Queue: $0.45,\ v{:}0.55$.

*Merge 3.* Merge to the root.

Depths: the $0.45$ symbol is at depth $1$; the $0.30$ symbol at depth $2$; the $0.15$ and $0.10$ symbols at depth $3$. Codewords: $0$, $10$, $110$, $111$.

$$L = 0.45(1) + 0.30(2) + 0.15(3) + 0.10(3) = 0.45+0.60+0.45+0.30 = 1.80 \text{ bits.}$$

**Sanity check.** $H = 1.782$ bits (computed in the previous part), so $H \le L = 1.80 < H+1$ ✓ — and the excess over entropy is only $0.018$ bits. Compare with the Shannon code's $L = 2.35$ on the same source: the Shannon lengths $(2,2,3,4)$ wasted $0.55$ bits per symbol, because they ignore how the rounding interacts across symbols. Kraft sum here: $\tfrac12+\tfrac14+\tfrac18+\tfrac18 = 1$ ✓, full tree.
:::

:::pitfall[Ties and the shape of the tree]
Ties in step 2 may be broken arbitrarily, and different choices give *different* codes with *different* codeword lengths — but always the same expected length. In the dyadic example, merging $B$ with $A$ instead of with $E$ is not allowed (their weights are not the two smallest), but where genuine ties occur the resulting trees can look quite different. Implementations that must interoperate therefore fix a deterministic tie-breaking rule, or transmit code lengths explicitly.
:::

## Optimality of Huffman Codes {#optimality}

<!-- section: optimality -->

Huffman's algorithm is greedy, and greedy algorithms are usually wrong. That this one is right needs proof, and the proof is a model of its kind: two structural lemmas about optimal codes, then an induction that says merging is harmless.

Throughout, order the probabilities $p_1 \ge p_2 \ge \cdots \ge p_m$ and call a prefix code **optimal** for $p$ if it minimises $L = \sum_i p_i \ell_i$ among all prefix codes.

:::lemma[Structure of an optimal code]{#huffman-lemma}
For any distribution $p$ with $p_1 \ge \cdots \ge p_m$ there is an optimal prefix code such that:

1. $p_j > p_k \implies \ell_j \le \ell_k$ (more probable symbols get no longer codewords);
2. the two longest codewords have equal length;
3. the two longest codewords differ only in their last bit — that is, they are siblings in the tree — and they may be taken to belong to the two least probable symbols $x_{m-1}$ and $x_m$.
:::

:::proof
**(1)** Let $C$ be optimal and suppose $p_j > p_k$ but $\ell_j > \ell_k$. Form $C'$ by swapping the codewords of $x_j$ and $x_k$; $C'$ is still a prefix code with the same multiset of lengths. The change in expected length is

$$L(C') - L(C) = p_j\ell_k + p_k\ell_j - p_j\ell_j - p_k\ell_k = (p_j - p_k)(\ell_k - \ell_j) < 0,$$

since $p_j - p_k > 0$ and $\ell_k - \ell_j < 0$. That contradicts optimality of $C$, so no such pair exists.

**(2)** Suppose the longest codeword $c$ is strictly longer than every other. No other codeword has $c$ as a prefix (prefix-freeness), and no other codeword is a prefix of $c$; deleting the last bit of $c$ therefore keeps the code prefix-free — the shortened string cannot be a prefix of another codeword, since such a codeword would then have the shortened string as a prefix and be at least as long as $c$, contradicting uniqueness of the maximum. The deletion strictly decreases $L$, contradicting optimality.

**(3)** By (2) there are at least two codewords of maximal length $\ell_{\max}$. Take one, $c$; its sibling (the string agreeing with $c$ except in the last bit) must be a codeword or have a codeword as a proper prefix — otherwise the subtree hanging there is empty and $c$ could be shortened, as in (2). Since $c$ has maximal length, the sibling must itself be a codeword. So maximal-length codewords come in sibling pairs. Finally, by (1) the symbols with maximal length are among the least probable; permuting codewords of equal length does not change $L$, so we may relabel so that the sibling pair belongs to $x_{m-1}$ and $x_m$.
:::

:::theorem[Optimality of Huffman coding]{#huffman-optimality}
For every distribution $p$ on a finite alphabet, the Huffman code is optimal: no prefix code (equivalently, by Kraft–McMillan, no uniquely decodable code) has smaller expected length.
:::

:::proof
Induction on the alphabet size $m$.

*Base case $m=2$.* Any prefix code needs two distinct codewords, so $L \ge 1$; Huffman assigns $0$ and $1$ and achieves $L = 1$.

*Induction step.* Assume Huffman is optimal for every distribution on $m-1$ symbols. Given $p_1\ge\cdots\ge p_m$, let $p'$ be the distribution on $m-1$ symbols obtained by merging the two smallest into one symbol of probability $p_{m-1}+p_m$.

First, a bookkeeping identity. Codes on the merged alphabet and codes on the original alphabet in which $x_{m-1}, x_m$ are siblings correspond one to one: split the merged symbol's codeword $c$ into $c0$ and $c1$, or conversely delete the last bit. Under this correspondence the expected lengths differ by a fixed amount,

$$L(C) = L(C') + (p_{m-1}+p_m), \tag{$\ast$}$$

because the two split symbols each gain one bit, contributing $(p_{m-1}+p_m)\cdot 1$, while every other symbol is unchanged.

Now let $C_m$ be the Huffman code for $p$. By construction it is obtained by splitting the merged symbol of the Huffman code $C'_{m-1}$ for $p'$, so $L(C_m) = L(C'_{m-1}) + p_{m-1}+p_m$.

Let $C^{*}$ be any optimal code for $p$. By Lemma *Structure of an optimal code* we may assume $x_{m-1}$ and $x_m$ are siblings in $C^{*}$; merging them gives a prefix code $D'$ for $p'$ with $L(C^{*}) = L(D') + p_{m-1}+p_m$ by $(\ast)$. By the induction hypothesis $L(C'_{m-1}) \le L(D')$. Therefore

$$L(C_m) = L(C'_{m-1}) + p_{m-1}+p_m \;\le\; L(D') + p_{m-1}+p_m \;=\; L(C^{*}).$$

Since $C^{*}$ was optimal, $L(C_m) = L(C^{*})$ and the Huffman code is optimal too.
:::

The proof also explains *why* greed is safe. The structure lemma says every optimal code contains the decision "make the two rarest symbols siblings" somewhere inside it; the algorithm simply makes that decision first, and identity $(\ast)$ shows that doing so costs a fixed amount regardless of what happens later.

:::corollary[Huffman codes obey the fundamental bound]{#huffman-bound}
The Huffman expected length $L^{*}$ satisfies

$$H(p) \;\le\; L^{*} \;<\; H(p) + 1 ,$$

with $L^{*} = H(p)$ if and only if every $p_i$ is a power of $1/2$.
:::

:::proof
The lower bound and the equality condition come from the entropy lower bound for uniquely decodable codes. For the upper bound, the Shannon code is a prefix code with $L < H+1$, and $L^{*} \le L$ by optimality.
:::

:::corollary[Huffman coding of blocks approaches the entropy rate]{#huffman-blocks}
Let $L_n^{*}$ be the expected length of the Huffman code applied to blocks of $n$ symbols of a stationary source. Then

$$\frac{H(X_1,\dots,X_n)}{n} \;\le\; \frac{L^{*}_n}{n} \;<\; \frac{H(X_1,\dots,X_n)}{n} + \frac1n, \qquad\text{so}\qquad \frac{L^{*}_n}{n}\longrightarrow h .$$
:::

:::proof
Apply the previous corollary to the single random variable $X^n$ over the alphabet $\mathcal{X}^n$, then divide by $n$ and let $n\to\infty$, using the definition of the entropy rate.
:::

:::intuition
Huffman gives you the best possible "comma-free" code, and the worst it can ever be is one bit per symbol above the theoretical floor.

That one bit is entirely the fault of integer arithmetic: a symbol of probability $0.9$ deserves a codeword of length $0.152$ bits and gets one of length $1$. Blocking symbols together spreads a single rounding error over many symbols, which is why the excess shrinks like $1/n$.
:::

:::example[When the one-bit gap really bites]
A binary source has $p(1) = 0.99$. Compute $H$, the Huffman expected length, and the efficiency. Then Huffman-code blocks of two symbols and recompute.
:::

:::solution
*Single symbols.* $H = -0.99\log 0.99 - 0.01\log 0.01 = 0.99(0.0145) + 0.01(6.644) = 0.0808$ bits.

There are only two symbols, so the only prefix code is $\{0,1\}$ and $L = 1$ bit. Efficiency $H/L = 8.1\%$; the excess is $0.919$ bits — nearly the whole allowed bit.

*Pairs.* The block probabilities are $11{:}0.9801$, $10{:}0.0099$, $01{:}0.0099$, $00{:}0.0001$. Huffman merges $00$ with $01$ ($0.0100$), then that with $10$ ($0.0199$), then with $11$. Lengths: $11 \to 1$, $10 \to 2$, $01\to 3$, $00 \to 3$.

$$L_2 = 0.9801(1) + 0.0099(2) + 0.0099(3) + 0.0001(3) = 0.9801+0.0198+0.0297+0.0003 = 1.0299 \text{ bits per pair,}$$

i.e. $0.515$ bits per symbol.

**Sanity check.** $H \le L_2/2 < H + 1/2$: indeed $0.0808 \le 0.515 < 0.5808$ ✓. Blocking halved the per-symbol cost from $1$ to $0.515$, exactly as the $1/n$ overhead predicts, and blocks of eight would bring it to about $0.081 + 0.125 = 0.206$. To actually reach $0.0808$ one needs blocks of thousands — or arithmetic coding, which is the subject of the next part.
:::

:::pitfall[Optimal does not mean good]
Huffman is optimal *within the class of symbol codes for the given model*. It cannot exploit memory (a first-order Huffman code on English text ignores that `q` is followed by `u`), it cannot spend a fractional bit, and it is helpless if the probabilities are wrong. Optimality is always relative to a class and a model; both restrictions are severe.
:::

## Huffman Coding in Practice {#practical-huffman}

<!-- section: practical-huffman -->

Real formats — DEFLATE, JPEG, MP3 — use Huffman codes, but never in the naive form of the algorithm above. Four engineering issues dominate.

:::definition[Canonical Huffman code]{#canonical-huffman}
A **canonical** Huffman code is the code obtained from a length vector $(\ell_1,\dots,\ell_m)$ by sorting symbols by $(\ell_i, i)$ and assigning codewords in increasing numerical order, incrementing the code value by $1$ at each symbol and shifting left when the length increases — exactly the cumulative construction used in the proof of Kraft's converse.
:::

:::proposition[Canonical codes are as good and cheaper to transmit]{#canonical-optimal}
A canonical Huffman code has the same codeword lengths, and hence the same expected length, as the Huffman code it is derived from; and it is fully determined by the length vector alone.
:::

:::proof
The construction assigns to the symbol of length $\ell_i$ the interval $[w_i, w_i + 2^{-\ell_i})$ of the Kraft proof, so lengths are preserved and the code is prefix-free; expected length depends only on lengths. Since the assignment is a deterministic function of the sorted lengths, decoder and encoder agree given the lengths alone: a table of $m$ small integers rather than $m$ variable-length bit strings.
:::

That proposition is why DEFLATE transmits a list of code lengths, themselves run-length and Huffman coded, rather than a tree. It also makes decoding fast: canonical codes can be decoded by comparing the input register against one threshold per length, without walking a tree.

- **Length-limited Huffman.** Hardware decoders need a bound $\ell_{\max}$ (typically $15$ or $16$) so that a lookup table fits in cache. The package-merge algorithm finds the optimal code subject to $\ell_i \le \ell_{\max}$ in $O(m\,\ell_{\max})$ time; the cost in expected length is usually a fraction of a percent.
- **Adaptive Huffman.** The FGK and Vitter algorithms maintain the tree as symbols arrive, so the encoder need not make a first pass or transmit a table. They pay in speed and in a small redundancy, and have largely been displaced by adaptive arithmetic coding.
- **Blocking and context.** Since Huffman cannot spend fractional bits, real codecs apply it to *derived* symbols that are already close to independent — DEFLATE Huffman-codes literal/length and distance symbols produced by an LZ77 pass; JPEG Huffman-codes (run, size) pairs produced by run-length coding the quantised DCT coefficients.

:::theorem[Worst-case codeword length]{#huffman-max-length}
For an alphabet of size $m$, no Huffman codeword is longer than $m-1$ bits, and this bound is attained — for example by probabilities proportional to the Fibonacci numbers $1,1,2,3,5,\dots$
:::

:::proof
Each merge in the algorithm increases by one the depth of the symbols in the merged subtrees, and there are exactly $m-1$ merges, so no depth can exceed $m-1$. Attainment: if $p_i \propto F_i$ with $F_{k+1} = F_k + F_{k-1}$, then at every step the newly created node has weight equal to the *next* Fibonacci number, hence is again one of the two smallest, so every merge involves the node created in the previous step. The tree degenerates into a path and the rarest symbol receives $m-1$ bits.
:::

:::example[Huffman inside JPEG]
In baseline JPEG, an $8\times8$ block's $63$ quantised AC coefficients are converted to (run-length, magnitude-category) symbols, which are Huffman-coded; the extra bits identifying the value within a category are appended raw. Why is the category trick used instead of Huffman-coding the coefficient values directly?
:::

:::solution
A coefficient can take thousands of values, so a direct Huffman table would need thousands of entries — expensive to transmit and to store — while most entries would be used a handful of times per image.

Grouping values by magnitude category ($\pm1$; $\pm2,\pm3$; $\pm4..\pm7$; …) reduces the alphabet to about $16$ categories crossed with $16$ run lengths, i.e. a table of about $256$ entries. Within a category of size $2^{k}$, all values are nearly equiprobable, so spending $k$ raw bits on them costs almost nothing above their entropy.

**Sanity check.** The scheme is exactly the Shannon-code idea applied twice: the category carries $\log(1/\Pr[\text{category}])$ bits of genuinely skewed information and is worth Huffman-coding; the within-category offset carries $k$ bits of nearly uniform information and is not. Huffman-coding a uniform alphabet of size $2^k$ gives codewords of exactly $k$ bits, so the raw bits lose nothing — the table is saved for free.
:::

## Common Mistakes

- **Assuming Huffman achieves the entropy exactly.** It achieves $L < H+1$; equality holds only for dyadic probabilities. For a very skewed binary source the gap approaches a full bit, which can be a factor of ten in rate.
- **Comparing Huffman codes by their codewords instead of their lengths.** Tie-breaking changes the codewords; only the length vector, and hence $L$, is canonical.
- **Forgetting the cost of the table.** A two-pass Huffman coder must transmit the code (or the lengths). On small inputs this overhead can exceed the savings, which is why DEFLATE offers a fixed, pre-agreed table as an option.
- **Assuming the rarest symbol gets a short codeword because the tree is "balanced".** In the worst case it gets $m-1$ bits; Huffman trees are balanced only when the distribution is near uniform.
- **Using a stale model.** Huffman assumes the probabilities are known and fixed. On data whose statistics drift, adaptive coding, or re-estimating per block, is essential.
- **Believing Huffman handles memory.** Symbol-by-symbol Huffman coding is blind to correlation; the gain from context modelling usually dwarfs the gain from optimal symbol coding.

Huffman coding is optimal and still leaves up to one bit per symbol on the table, because a codeword is an integral number of bits. Arithmetic coding removes that restriction by refusing to give any symbol a codeword at all: the entire message is mapped to a single number, and only that number is transmitted. The cost is $-\log p(x^n) + 2$ bits for the whole message, so the rounding loss is amortised over the whole file rather than paid per symbol.

## The Core Idea: Messages as Subintervals {#idea}

<!-- section: idea -->

Arrange the strings of length $n$ in lexicographic order and lay their probabilities end to end along $[0,1)$. Each string then owns a subinterval whose *length* is its probability and whose *position* identifies it. Naming a message means naming a point in its interval.

:::definition[Cumulative distribution and the interval of a string]{#cdf-interval}
For a distribution $p$ on a totally ordered set, the **cumulative distribution function** is $F(x) = \sum_{a \le x} p(a)$, and the interval assigned to $x$ is

$$I(x) = \bigl[\,F(x) - p(x),\ F(x)\,\bigr),$$

of length exactly $p(x)$. Distinct symbols own disjoint intervals, and the intervals tile $[0,1)$.
:::

:::definition[Modified cumulative function and the Shannon–Fano–Elias code]{#sfe-code}
The **modified cumulative function** is the midpoint of the interval,

$$\bar F(x) = \sum_{a<x} p(a) + \tfrac12 p(x).$$

The **Shannon–Fano–Elias code** transmits the first

$$\ell(x) = \left\lceil \log\frac{1}{p(x)} \right\rceil + 1$$

bits of the binary expansion of $\bar F(x)$; write $\lfloor \bar F(x)\rfloor_{\ell(x)}$ for that truncation.
:::

The extra bit in $\ell(x)$ buys prefix-freeness, and the following proof shows exactly where it is spent.

:::theorem[The Shannon–Fano–Elias code is prefix-free, with $L < H+2$]{#sfe-theorem}
The code above is a prefix code, and its expected length satisfies

$$H(p) + 1 \;\le\; L \;<\; H(p) + 2 .$$
:::

:::proof
*Prefix-freeness.* Truncating a number $z\in[0,1)$ to $\ell$ bits loses less than $2^{-\ell}$, so

$$0 \;\le\; \bar F(x) - \lfloor \bar F(x)\rfloor_{\ell(x)} \;<\; 2^{-\ell(x)} .$$

A codeword $c$ of length $\ell$ stands for the dyadic interval $[0.c,\, 0.c + 2^{-\ell})$, and by the display this interval contains $\bar F(x)$. Moreover

$$2^{-\ell(x)} = 2^{-\lceil \log(1/p(x))\rceil - 1} \;\le\; \frac{p(x)}{2},$$

so the dyadic interval has length at most $p(x)/2$ and contains the midpoint $\bar F(x)$ of $I(x)$; since the midpoint is at distance $p(x)/2$ from each end of $I(x)$, the dyadic interval lies entirely inside $I(x)$. The intervals $I(x)$ are disjoint for distinct $x$, so the dyadic intervals are disjoint, and as established in the proof of Kraft's inequality, disjoint dyadic intervals correspond to codewords neither of which is a prefix of the other.

*Expected length.* Taking expectations of $\ell(x) = \lceil\log(1/p(x))\rceil + 1$ and using $t \le \lceil t\rceil < t+1$,

$$H(p) + 1 \;\le\; \sum_x p(x)\left(\log\frac{1}{p(x)} + 1\right) \le L < \sum_x p(x)\left(\log\frac{1}{p(x)} + 2\right) = H(p)+2 .$$
:::

Two bits of overhead is worse than Huffman's one — on single symbols. The point is that the construction never mentions the alphabet: apply it to the alphabet $\mathcal{X}^n$ of whole messages and the overhead becomes $2/n$ bits per symbol, with no enormous code table, because the interval of $x^n$ can be computed incrementally. That incremental computation is arithmetic coding.

:::definition[Arithmetic code and tag]{#arithmetic-tag}
An **arithmetic code** for a model $p$ over $\mathcal{X}^n$ maps the message $x^n$ to the interval $I(x^n) \subseteq [0,1)$ of length $p(x^n)$ obtained by nesting the per-symbol subdivisions, and transmits enough binary digits of a point inside it — the **tag** — to identify the interval uniquely.
:::

:::intuition
The unit interval is a ruler. Every possible message claims a segment of the ruler in proportion to how likely it is: likely messages get wide segments, unlikely ones get slivers.

To send a message you point at a spot inside its segment. Wide segments can be located with few digits of precision, slivers need many — and "number of digits needed" is $\log(1/\text{width}) = \log(1/p)$, which is exactly the ideal codelength. Arithmetic coding is the observation that pointing precisely is the same as compressing.
:::

:::example[Encoding a three-symbol message]
A source emits $A$ with $p=0.8$ and $B$ with $p=0.2$, with $F(A) = 0$ and $F(B) = 0.8$ as the interval bases. Encode `AAB`.
:::

:::solution
Start with $[\text{low},\text{high}) = [0,1)$, width $1$.

*First $A$:* $[0 + 1(0),\ 0 + 1(0.8)) = [0,\,0.8)$, width $0.8$.

*Second $A$:* $[0 + 0.8(0),\ 0 + 0.8(0.8)) = [0,\,0.64)$, width $0.64$.

*Then $B$:* $[0 + 0.64(0.8),\ 0 + 0.64(1.0)) = [0.512,\,0.64)$, width $0.128$.

**Sanity check.** The final width is $0.8 \times 0.8 \times 0.2 = 0.128$ ✓ — the probability of `AAB`. The ideal codelength is $\log(1/0.128) = 2.97$ bits, so about $3$ bits should suffice. Indeed $0.101 _2 = 0.625$ lies in $[0.512, 0.64)$, and no shorter binary fraction does, since the only $2$-bit candidates are $0.00, 0.25, 0.50, 0.75$. Three bits for three symbols beats the naive $3$ bits only marginally here, but the source entropy is $0.722$, so on long messages the coder approaches $0.722$ bits per symbol while Huffman is stuck at $1$.
:::

## Interval Narrowing, Renormalization, and Precision {#interval-narrowing}

<!-- section: interval-narrowing -->

The encoder is one line of arithmetic repeated once per symbol.

:::recipe[Arithmetic encoder update]{#arithmetic-update}
Maintain $[\text{low}, \text{high})$, initialised to $[0,1)$. For each symbol $s$ with probability $p(s)$ and cumulative base $F^{-}(s) = \sum_{a<s}p(a)$ — both allowed to depend on all previously coded symbols — set $w = \text{high}-\text{low}$ and

$$\text{low}' = \text{low} + w\,F^{-}(s), \qquad \text{high}' = \text{low} + w\bigl(F^{-}(s) + p(s)\bigr).$$
:::

:::proposition[The final width is the message probability]{#arithmetic-width}
After encoding $x^n$ the interval has width

$$\text{high} - \text{low} = \prod_{i=1}^{n} p(x_i \mid x^{i-1}) = p(x^n),$$

so $\log(1/\text{width}) = -\log p(x^n)$ bits suffice to name it, whatever model supplied the conditional probabilities.
:::

:::proof
From the update rule, $\text{high}' - \text{low}' = w\,p(s)$: each step multiplies the width by the probability of the symbol just coded. Starting from width $1$ and multiplying across the message gives $\prod_i p(x_i\mid x^{i-1})$, which is $p(x^n)$ by the chain rule.
:::

This proposition is the reason arithmetic coding is *model-agnostic*. The coder never sees a table of symbol probabilities; it consumes a conditional distribution per symbol, and whatever model produces them — order-0, order-5 context, a neural network — the output length is $-\log p(x^n)$ plus a constant. Modelling and coding are cleanly separated, which is arithmetic coding's true advantage over Huffman.

The obvious implementation problem is that $\text{low}$ and $\text{high}$ converge and would need unbounded precision. The fix is to notice that once the interval lies wholly in one half of $[0,1)$, the leading bit of every point in it is decided and can be emitted.

:::recipe[Renormalization: E1, E2 and E3 scalings]{#renormalization}
After each symbol, repeat while one of the conditions holds:

- **E1** ($\text{high} \le \tfrac12$): the interval is in the lower half. Output the bit $0$, then map $[l,h) \mapsto [2l, 2h)$.
- **E2** ($\text{low} \ge \tfrac12$): the interval is in the upper half. Output the bit $1$, then map $[l,h)\mapsto[2l-1, 2h-1)$.
- **E3** ($\tfrac14 \le \text{low} < \tfrac12 \le \text{high} < \tfrac34$): the interval straddles $\tfrac12$ but is narrow. Increment a counter of *pending* bits, then map $[l,h) \mapsto [2l-\tfrac12,\ 2h-\tfrac12)$. When the next E1 or E2 finally outputs a bit $b$, emit that bit followed by one copy of $\bar b$ per pending count.
:::

:::proposition[Renormalization is lossless and keeps the width above $1/4$]{#renorm-correct}
The E1/E2 maps are the affine maps that send the relevant half of $[0,1)$ onto $[0,1)$; emitting the corresponding bit and rescaling therefore preserves the identity of the final interval. After the loop terminates the width exceeds $\tfrac14$, so the registers never lose more than two bits of precision.
:::

:::proof
The map $x\mapsto 2x$ on $[0,\tfrac12)$ and $x \mapsto 2x-1$ on $[\tfrac12,1)$ are exactly "delete the leading bit after the binary point", which is the bit just emitted; so the remaining digits of the tag are unchanged. The loop exits only when none of E1, E2, E3 applies, i.e. when $\text{low}<\tfrac14$ and $\text{high}>\tfrac12$, or $\text{low}<\tfrac12$ and $\text{high}>\tfrac34$; in either case $\text{high}-\text{low} > \tfrac14$.
:::

The E3 rule is the subtle one. An interval such as $[0.499, 0.501)$ is tiny but straddles the midpoint, so no bit is yet determined; scaling about the midpoint keeps the registers full while recording that whatever the first undetermined bit turns out to be, the next bits are its complement. Without E3 an implementation with finite registers eventually underflows and the code becomes ambiguous.

:::intuition
You keep zooming into a smaller and smaller portion of the ruler. As soon as the whole remaining segment lies to the left of the halfway mark you know the first digit is $0$; write it down and blow the left half back up to full size, recovering a bit of working precision.

E3 is the "I know the next two bits are either $01\ldots1$ or $10\ldots0$" case: you cannot name the first bit yet, but you know all the following ones will be its opposite, so you count them and fill them in later.
:::

:::example[One narrowing step and its renormalization]
The current interval is $[0.1, 0.6)$. The next symbol has $F^{-} = 0.3$ and $p = 0.4$. Perform the update and any renormalization.
:::

:::solution
Width $w = 0.5$. The update gives

$$\bigl[\,0.1 + 0.5(0.3),\ 0.1 + 0.5(0.3+0.4)\,\bigr) = [\,0.25,\ 0.45\,),$$

of width $0.20 = 0.5 \times 0.4$ ✓.

Since $\text{high} = 0.45 \le 0.5$, rule **E1** applies: output the bit $0$ and rescale to $[0.5, 0.9)$.

Now $\text{low} = 0.5 \ge 0.5$, so **E2** applies: output the bit $1$ and rescale to $[2(0.5)-1,\ 2(0.9)-1) = [0, 0.8)$. No rule applies to $[0,0.8)$, so the loop stops.

**Sanity check.** Two bits (`01`) were emitted and the width went from $0.20$ to $0.80$, a factor of $4 = 2^2$ — one doubling per emitted bit, as the proposition requires. And `01` is right: the final interval $[0.25,0.45)$ sits inside $[0.25, 0.5)$, whose points all begin $0.01\ldots$ in binary ✓.
:::

:::pitfall[Finite precision needs integer arithmetic, not floating point]
Encoder and decoder must agree *bit for bit*. Floating-point rounding differs across compilers and platforms, so any real implementation keeps `low` and `high` as fixed-width integers (say 32 bits), computes $w\,F^{-}(s)$ with integer multiply-then-divide by the cumulative total, and guarantees that no interval ever becomes empty by keeping the frequency counts below a bound related to the register width. Carry propagation out of `low` must also be handled — the pending-bit counter of E3 is exactly the mechanism that does it.
:::

## Termination, Decoding, and the Coding Theorem for Arithmetic Codes {#termination}

<!-- section: termination -->

The interval determines the message; a *transmitted tag* determines the message only if the decoder also knows where to stop. Two devices are used, and one theorem settles the cost of both.

:::theorem[Arithmetic coding is within two bits of optimal]{#arithmetic-optimal}
Encoding a message $x^n$ with an arithmetic coder driven by the model $p$ produces at most

$$\ell(x^n) \;=\; \left\lceil \log\frac{1}{p(x^n)}\right\rceil + 1 \;<\; \log\frac{1}{p(x^n)} + 2$$

bits, and the resulting code is prefix-free. Consequently the expected rate satisfies

$$\frac{L_n}{n} \;<\; \frac{H(X_1,\dots,X_n)}{n} + \frac2n \;\longrightarrow\; h .$$
:::

:::proof
The final interval has width $p(x^n)$ by Proposition *The final width is the message probability*. Applying the Shannon–Fano–Elias construction to the alphabet $\mathcal{X}^n$ — transmitting the first $\lceil\log(1/p(x^n))\rceil + 1$ bits of the midpoint of that interval — gives a prefix code by the Shannon–Fano–Elias theorem, with the stated length. Taking expectations,

$$L_n = E[\ell(X^n)] < E\left[\log\frac{1}{p(X^n)}\right] + 2 = H(X_1,\dots,X_n) + 2 .$$

Dividing by $n$ and letting $n\to\infty$ gives the rate claim, since $H(X_1,\dots,X_n)/n \to h$ by definition of the entropy rate.
:::

Compare this with Huffman's $L^{*}_n < H(X^n)+1$ for blocks: the constant is worse, but Huffman needs a table of size $|\mathcal{X}|^n$ to achieve it while arithmetic coding needs one register and a model. Two bits *for the whole file* is the practical meaning of the theorem.

:::recipe[Termination strategies]{#arithmetic-termination}
1. **End-of-file symbol.** Reserve a symbol EOF with a small probability, and code it as the last symbol. The decoder stops when it decodes EOF. Cost: $\log(1/p(\text{EOF}))$ bits, plus a tiny dilution of every other symbol's probability.
2. **Explicit length.** Transmit $n$ in a header (e.g. with an Elias code) and decode exactly $n$ symbols. Cost: about $\log n + 2\log\log n$ bits.
3. **Flush bits.** Emit enough bits of the tag to pin it inside the final interval — two bits after renormalization, plus any pending E3 bits — and let the container format supply the length.
:::

:::recipe[Arithmetic decoding]{#arithmetic-decoding}
The decoder mirrors the encoder. Maintain the same $[\text{low},\text{high})$ and a *value* register holding the received tag bits.

1. Compute $t = \dfrac{\text{value} - \text{low}}{\text{high}-\text{low}}$, the position of the tag within the current interval.
2. Find the unique symbol $s$ with $F^{-}(s) \le t < F^{-}(s)+p(s)$; emit $s$.
3. Apply the same narrowing update for $s$, then the same renormalization, shifting new bits into the value register whenever the encoder would have emitted one.
4. Repeat until EOF or the known length is reached.
:::

:::proposition[Decoder correctness]{#decoder-correct}
If the transmitted tag lies in $I(x^n)$, the decoder recovers $x^n$ exactly.
:::

:::proof
By induction on $i$. The intervals of the possible first symbols partition $[0,1)$, and the tag lies in $I(x^n)\subseteq I(x_1)$, so step 2 selects $s = x_1$. After the update the decoder's interval is $I(x_1)$, the encoder's interval after one symbol, and the tag still lies in $I(x^n)\subseteq I(x_1x_2)$. The inductive step repeats the argument inside the rescaled interval, and the renormalization maps applied by both sides are identical, so the registers stay synchronised.
:::

:::intuition
The decoder is the encoder run as a question-answering machine: "given where the pointer is, which segment is it in?" Each answer is one symbol, and narrowing to that segment zooms in to ask the same question again.

Because the two sides apply the same updates in the same order, the decoder needs no information beyond the tag and the model — and if the model is adaptive, it can update it from the symbols it has already decoded, exactly as the encoder did.
:::

:::example[Cost of the two termination strategies]
A file of $n = 10^{6}$ symbols is coded at $H = 2$ bits/symbol. Compare an EOF symbol of probability $10^{-6}$ with an explicit length header.
:::

:::solution
*EOF symbol.* Coding it costs $\log(1/10^{-6}) = 19.9$ bits once. But giving EOF probability $10^{-6}$ also scales every other symbol's probability by $(1-10^{-6})$, costing $-\log(1-10^{-6}) \approx 1.44\times10^{-6}$ bits per symbol, i.e. $1.44$ bits over the file. Total: about $21.4$ bits.

*Explicit length.* An Elias delta code for $n = 10^{6}$ uses about $\log n + 2\log\log n + 1 \approx 19.9 + 2(4.3) + 1 = 29.5$ bits.

*Flush.* Either way, two extra bits pin the tag.

**Sanity check.** The file itself occupies $2\times10^{6}$ bits, so the termination overhead is about $10^{-5}$ of the total — utterly negligible, which is why the choice is made on engineering grounds (streaming favours EOF; random access favours an explicit length). The theorem's "$+2$ bits" is of the same order, confirming that arithmetic coding's inefficiency is a constant, not a rate.
:::

## Common Mistakes

- **Waiting until the end to emit bits.** Renormalization emits each bit as soon as it is determined, so memory use is constant and the coder streams. An implementation that computes the exact final interval in rational arithmetic is correct but useless.
- **Omitting the E3 (underflow) rule.** Without it an interval straddling $\tfrac12$ shrinks below the register precision and encoder and decoder diverge.
- **Blaming the coder for poor compression.** Arithmetic coding is within two bits of $-\log p(x^n)$ *for the model it is given*. All remaining compression performance is the model's; this is why modern compressors put their effort into context mixing, not into the coder.
- **Forgetting to allocate probability to termination.** Without an EOF symbol or an explicit length the decoder cannot know when to stop and will happily decode arbitrarily many further symbols.
- **Using floating point.** Encoder and decoder must perform bit-identical arithmetic; fixed-point integers with a controlled total frequency are mandatory.
- **Assuming arithmetic coding is always the right choice.** It has higher per-symbol cost than a canonical Huffman decoder, and for nearly uniform alphabets the one-bit Huffman penalty is negligible. ANS (asymmetric numeral systems) now occupies much of this ground, achieving arithmetic-coding compression at table-driven speeds.

Every coder so far has been handed a probability model. Real files arrive without one. A **universal** compressor must learn the structure while coding and still approach the entropy rate of whatever source produced the data. The Lempel–Ziv family does this with no probabilities at all: it compresses by noticing that text repeats itself.

## Parsing a String into Phrases {#dictionary}

<!-- section: dictionary -->

:::definition[LZ78 parsing]{#lz78-parsing}
The **LZ78 parsing** of a string $x_1x_2\cdots x_n$ is the greedy decomposition into phrases in which each new phrase is the shortest prefix of the remaining input that has not appeared as an earlier phrase. Each phrase therefore equals some earlier phrase extended by one symbol, and is transmitted as the pair

$$(\text{index of that earlier phrase},\ \text{the new symbol}).$$

Write $c(n)$ for the number of phrases produced.
:::

:::definition[LZW dictionary]{#lzw-dictionary}
**LZW** (Lempel–Ziv–Welch, 1984) is the variant that keeps the phrases in an explicit **dictionary** initialised with every single symbol of the alphabet, so that only an index — never a raw symbol — is ever transmitted. Encoder and decoder build identical dictionaries from the code stream alone; the dictionary is never sent.
:::

The two descriptions differ only in bookkeeping, and LZW is what GIF and the Unix `compress` utility implement. The essential point is shared: the code is a sequence of *pointers into text the decoder has already reconstructed*.

:::theorem[How many phrases a string can have]{#phrase-count}
If a string of length $n$ over an alphabet of size $D \ge 2$ is parsed into $c$ distinct phrases, then

$$c \;\le\; \frac{C\,n}{\log_D n}$$

for an absolute constant $C$ and all $n \ge 2$; that is, $c = O(n/\log n)$.
:::

:::proof
The phrases are distinct strings whose lengths sum to $n$, so $n$ is at least the smallest possible total length of $c$ distinct non-empty strings — which is attained by taking the $c$ shortest ones.

First count the short strings. The number of non-empty strings of length at most $m$ is

$$D + D^2 + \cdots + D^{m} \;=\; \frac{D\bigl(D^{m}-1\bigr)}{D-1} \;\le\; 2D^{m},$$

using $D/(D-1)\le 2$ for $D \ge 2$.

Let $m$ be the largest integer with $D^{m} \le c/4$. Then at most $2D^{m} \le c/2$ of the phrases have length $\le m$, so at least $c/2$ of them have length greater than $m$, and since the lengths sum to $n$,

$$n \;\ge\; \frac{c}{2}\,m .$$

Maximality of $m$ gives $D^{m+1} > c/4$, hence $m > \log_D c - \log_D 4 - 1$. Substituting,

$$n \;\ge\; \frac{c}{2}\bigl(\log_D c - \log_D 4 - 1\bigr), \qquad\text{so}\qquad c\log_D c \;\le\; 2n + 3c \;\le\; 5n,$$

using $\log_D 4 \le 2$ and $c \le n$. Now split on the size of $c$. If $c \ge \sqrt n$ then $\log_D c \ge \tfrac12 \log_D n$, and the display gives $c \le 10n/\log_D n$. If instead $c < \sqrt n$, then $c < \sqrt n \le 10n/\log_D n$ because $\log_D n \le 10\sqrt n$ for all $n\ge2$. Either way the bound holds with $C = 10$.
:::

The theorem is the engine of the whole method: it says the number of pointers grows like $n/\log n$, so the total cost $c(n)\bigl(\log c(n) + \log D\bigr)$ grows like $n$ — a constant number of bits per symbol — and the entire question is what that constant turns out to be.

:::intuition
The first time you meet the phrase `the ` you must spell it out. After that you can say "entry 300". The dictionary grows, so later pointers are longer, but the phrases they name grow faster — and that race is what compression is.

A string cannot have too many *distinct* phrases, because distinct strings have to get longer: there are only $D^k$ strings of length $k$ to go around.
:::

:::example[LZW encoding of a repetitive string]
The alphabet is $\{A, B\}$ with initial dictionary $A \to 1$, $B \to 2$; the next free code is $3$. Encode `ABABABA`.
:::

:::solution
The encoder holds a phrase `cur` and emits a code only when `cur + c` is not yet in the dictionary.

`cur = "A"`, read `B`: `"AB"` unknown $\Rightarrow$ output **1** (`"A"`), add `"AB"` $=3$, set `cur = "B"`.

`cur = "B"`, read `A`: `"BA"` unknown $\Rightarrow$ output **2** (`"B"`), add `"BA"` $=4$, set `cur = "A"`.

`cur = "A"`, read `B`: `"AB"` known $\Rightarrow$ extend, `cur = "AB"`.

`cur = "AB"`, read `A`: `"ABA"` unknown $\Rightarrow$ output **3** (`"AB"`), add `"ABA"` $=5$, set `cur = "A"`.

`cur = "A"`, read `B`: `"AB"` known $\Rightarrow$ `cur = "AB"`.

`cur = "AB"`, read `A`: `"ABA"` known $\Rightarrow$ `cur = "ABA"`.

End of input: output **5** (`"ABA"`).

Output stream: $1, 2, 3, 5$ — four codes for seven characters.

**Sanity check.** Every dictionary addition is the phrase just emitted followed by the next input symbol (`AB`, `BA`, `ABA`), so the decoder, which sees the same emitted phrases, can replay every addition. Note the last code, $5$, names a phrase the algorithm learned *during this very string* — the mechanism by which LZW discovers structure it was never told about.
:::

## Encoding, Decoding, and the Self-Referential Case {#encoding-process}

<!-- section: encoding-process -->

:::recipe[LZW encoding]{#lzw-encoding}
1. Initialise the dictionary with the $D$ single symbols; set `cur` to the first input symbol.
2. For each subsequent symbol `c`: if `cur + c` is in the dictionary, set `cur = cur + c`; otherwise output the code of `cur`, add `cur + c` to the dictionary, and set `cur = c`.
3. At the end of the input, output the code of `cur`.
:::

:::recipe[LZW decoding]{#lzw-decoding}
1. Read the first code and emit its phrase; call it `prev`.
2. For each subsequent code $k$: if $k$ is in the dictionary, let `cur` be its phrase; **otherwise** let `cur` $=$ `prev` $+$ `prev`$[0]$. Emit `cur`, add `prev` $+$ `cur`$[0]$ to the dictionary, and set `prev` $=$ `cur`.
:::

The decoder runs one step behind the encoder — it adds an entry only after seeing the *next* code — and that one-step lag creates the only subtlety in the algorithm.

:::proposition[The exceptional code]{#lzw-exception}
A decoder can receive a code $k$ that is not yet in its dictionary. This happens exactly when the encoder used an entry it created on the immediately preceding step, and in that case the missing phrase is

$$\text{phrase}(k) \;=\; \texttt{prev} + \texttt{prev}[0],$$

so the decoder can always continue.
:::

:::proof
Suppose the encoder emits code $k$ for a phrase $w$ that it added one step earlier. By the encoding rule, the entry added at the previous step was $w = v + a$, where $v$ is the phrase emitted at the previous step (so $v = \texttt{prev}$ at the decoder) and $a$ is the input symbol that followed it. But the encoder emits $w$ next only if `cur` grew to $w$, which starts from `cur` $= a$: the symbol immediately after $v$ is $a$, and $w$ begins with that same symbol only if $w = v+a$ starts with $a$ — i.e. $v$ starts with $a$, so $a = v[0]$. Hence $w = v + v[0] = \texttt{prev} + \texttt{prev}[0]$, which the decoder already knows.

No other code can be missing: any $k$ emitted for an older entry was added at least two steps earlier, and the decoder is only one step behind.
:::

:::example[Decoding the stream and meeting the exception]
Decode $1, 2, 3, 5$ with initial dictionary $A = 1$, $B = 2$, next free code $3$.
:::

:::solution
Receive **1** $\to$ emit `"A"`; nothing to add yet. `prev = "A"`.

Receive **2** $\to$ phrase `"B"`; emit `"B"`, add `"A"+"B" = "AB"` $=3$. `prev = "B"`.

Receive **3** $\to$ phrase `"AB"`; emit `"AB"`, add `"B"+"A" = "BA"` $=4$. `prev = "AB"`.

Receive **5** $\to$ *not in the dictionary*. By the exceptional-code rule the phrase is `prev + prev[0] = "AB" + "A" = "ABA"`. Emit `"ABA"`, add `"AB"+"A" = "ABA"` $=5$. `prev = "ABA"`.

Output: `A` + `B` + `AB` + `ABA` = `ABABABA`.

**Sanity check.** The reconstruction equals the original input ✓, and the decoder's dictionary (`AB`$=3$, `BA`$=4$, `ABA`$=5$) is identical to the encoder's ✓ — built from the code stream alone, with no dictionary transmitted. The exception fired exactly where the proposition predicts: code $5$ was created by the encoder one step before it was used.
:::

:::theorem[Codelength of LZ78]{#lz-codelength}
Transmitting the $c(n)$ phrases of an LZ78 parsing, each as an index into the phrases so far plus one symbol, costs at most

$$\ell(x^n) \;\le\; c(n)\bigl(\log c(n) + \log D\bigr) \text{ bits},$$

which is $O(n)$ bits: by the phrase-count theorem $c(n) = O(n/\log_D n)$, while $\log c(n) \le \log n$, so the product is bounded by a constant multiple of $n$. The code therefore spends a bounded number of bits per symbol, and the content of the optimality theorem below is that the constant is exactly $h$.
:::

:::proof
There are $c(n)$ phrases; the index of the earlier phrase referenced by phrase $j$ is at most $j-1 < c(n)$ and so fits in $\lceil\log c(n)\rceil$ bits if a fixed width is used, and the appended symbol costs $\lceil \log D\rceil$ bits. Summing over the $c(n)$ phrases gives the bound.
:::

:::theorem[Asymptotic optimality of Lempel–Ziv]{#lz-optimality}
For any stationary ergodic source with entropy rate $h$, the LZ78 codelength satisfies

$$\limsup_{n\to\infty} \frac{1}{n}\,\ell(X^n) \;=\; h \quad\text{almost surely.}$$

Lempel–Ziv therefore attains the source coding bound *without being told the distribution*: it is universal over the class of all stationary ergodic sources on a finite alphabet.
:::

:::proof
We only sketch the argument; the full proof is in Cover and Thomas and is beyond the scope of this chapter. Two ingredients do the work.

*Lower bound.* $\liminf \frac1n \ell(X^n) \ge h$ is the converse to the source coding theorem: no uniquely decodable code beats the entropy rate.

*Upper bound.* The key step is **Ziv's inequality**: for any distinct parsing of $x^n$ into $c$ phrases, and for any $k$-th order Markov measure $Q$ on the source,

$$\log \frac{1}{Q(x^n)} \;\ge\; \sum_{\text{phrases}} \log(\text{number of phrases with the same $k$-symbol context}) \;\ge\; c\log c - c\,\kappa,$$

with $\kappa$ depending only on $k$ and $D$. Combining it with the phrase-count theorem shows $c(n)\log c(n)/n$ is asymptotically bounded by the $k$-th order conditional entropy $H(X_{k+1}\mid X_1,\dots,X_k)$; the ergodic theorem lets $k\to\infty$, and that conditional entropy decreases to $h$. Since the codelength is $c\log c$ up to lower-order terms, the limsup is at most $h$.
:::

:::intuition
LZ never estimates a probability. It nevertheless converges to the entropy rate, because *repetition is exactly what low entropy means*: a source with entropy rate $h$ produces about $2^{nh}$ typical strings of length $n$, so within a long enough window, phrases must start repeating, and the repetition rate is governed by $h$.

The dictionary is an empirical model that gets richer the longer you look. It is slower to converge than a well-chosen parametric model — its redundancy decays like $1/\log n$ rather than $\log n / n$ — but it needs no choosing.
:::

## Limits, Variants, and What Is Used in Practice {#limitations}

<!-- section: limitations -->

The optimality theorem is asymptotic in $n$ with an unbounded dictionary. Every real implementation departs from it, and the departures are what distinguish the formats.

- **Bounded dictionary.** GIF uses $12$-bit codes, i.e. $4096$ entries. Once full, an implementation either freezes the dictionary (and stops adapting) or emits a CLEAR code that resets it, paying the cost of relearning. Neither matches the theorem, whose conclusion needs $c(n)\to\infty$.
- **LZ77 instead of LZ78.** LZ77 (Ziv–Lempel 1977) emits triples (distance back, match length, next symbol) into a sliding window rather than indices into a dictionary of phrases. It is also universal, adapts faster to local statistics, and is what gzip (DEFLATE), zstd, LZMA and Brotli use, always with an entropy coder — usually Huffman or ANS — applied to the literals, lengths and distances.
- **Expansion on incompressible data.** On a string with no repeats every phrase is new, so $c(n) \approx n$ and the output is $n(\log n + \log D)$ bits, *longer* than the input. Formats therefore include a "stored" (uncompressed) block type, which caps the expansion at a few bytes per block.
- **Convergence speed.** LZ's redundancy over the entropy rate decays roughly like $O(1/\log n)$, so on a $10$ kB file it may be several tenths of a bit per symbol away from $h$. Context-model-plus-arithmetic compressors converge much faster and win decisively on small inputs; LZ wins on speed.

:::theorem[LZW cannot compress a memoryless uniform source]{#lz-incompressible}
If $X_1,\dots,X_n$ are i.i.d. uniform on an alphabet of size $D$, then $h = \log D$ and every lossless code — Lempel–Ziv included — has expected length at least $n\log D$ bits, so the expected compression ratio is at most $1$.
:::

:::proof
Uniformity gives $H(X) = \log D$ and independence gives $h = \log D$. The entropy lower bound for uniquely decodable codes applied to the block $X^n$ gives $E[\ell(X^n)] \ge H(X^n) = n\log D$. Since the raw encoding also costs $n\log D$ bits, no scheme can do better on average, and any scheme that shortens some inputs lengthens others by the no-free-lunch theorem.
:::

:::example[Why GIF is a poor choice for photographs]
A $256$-colour icon with large flat areas and a $256$-colour dithered photograph are both stored as GIF. Explain the difference in file size using the phrase-count bound.
:::

:::solution
*Icon.* Flat runs mean the parsing quickly builds long phrases: a run of $k$ identical pixels is covered by phrases of lengths $1,2,3,\dots$, so $c$ phrases cover about $c^2/2$ pixels and $c \approx \sqrt{2n}$. The cost is about $\sqrt{2n}(\log c + 8)$ bits instead of $8n$ — a ratio that improves as the file grows.

*Dithered photograph.* Dithering deliberately randomises neighbouring pixels, so repeats are rare, $c(n)\approx n/2$ or worse, and the cost approaches $n(\log c + 8) > 8n$ bits: LZW expands it, and only the stored-block escape keeps the file near its raw size.

**Sanity check.** The two cases bracket the theorem: the icon is a low-entropy-rate source where repetition is abundant, the dithered image an engineered high-entropy one where the incompressibility theorem applies with $\log D = 8$. The right tools are respectively PNG (LZ77 + Huffman, with a pixel predictor) and JPEG (lossy, escaping the entropy bound altogether).
:::

## Common Mistakes

- **Confusing LZ77 with LZ78/LZW.** LZ77 points backwards into the raw text with (distance, length) pairs; LZ78/LZW points into a dictionary of previously created phrases. The distinction matters for memory, for seeking, and for patent history.
- **Believing the dictionary is transmitted.** It is rebuilt by the decoder from the code stream. Sending it would defeat the purpose.
- **Mishandling the exceptional code.** An implementation that assumes every received code is already in the dictionary fails on inputs as short as `ABABABA`.
- **Expecting compression of random data.** The incompressibility theorem forbids it; LZ on random data expands by roughly $\log n$ bits per phrase.
- **Forgetting the CLEAR mechanism.** With a bounded dictionary and no reset, a compressor that has finished learning one file's statistics carries them, uselessly, into the next region of a heterogeneous file.
- **Quoting LZ's optimality without its hypotheses.** It is asymptotic, requires an unbounded dictionary, and holds for stationary ergodic sources. None of the three is exactly true of a real file on a real implementation.

Shannon–Fano coding is the first systematic construction of an efficient prefix code, described by Shannon in 1948 and refined by Fano the same year. It is no longer the method of choice — Huffman is optimal and barely harder — but it is the cleanest illustration of top-down code design, it is what Huffman was assigned to improve upon, and its analysis is where the bound $L < H+1$ was first established.

## The Splitting Construction {#construction}

<!-- section: construction -->

Two different constructions travel under the name "Shannon–Fano", and it is worth keeping them apart.

:::definition[Shannon's lengths]{#shannon-lengths}
**Shannon's code** assigns $\ell_i = \lceil \log(1/p_i)\rceil$ and realises those lengths by the cumulative construction of Kraft's converse: sort by decreasing probability, set $w_i = \sum_{j<i}p_j$, and take the first $\ell_i$ bits of the binary expansion of $w_i$.
:::

:::recipe[Fano's splitting algorithm]{#shannon-fano-construction}
**Fano's code** is built top-down.

1. Sort the symbols in non-increasing order of probability.
2. Split the sorted list into two consecutive groups whose total probabilities are as nearly equal as possible.
3. Append $0$ to every codeword in the first group and $1$ to every codeword in the second.
4. Recurse on each group until every group holds a single symbol.
:::

Both produce prefix codes — Shannon's by Kraft's converse, Fano's because the recursion builds a binary tree with the symbols at its leaves — and both satisfy the fundamental bound.

:::theorem[Shannon's code satisfies $H \le L < H+1$]{#sf-bound}
The Shannon code is a prefix code and its expected length obeys $H(p) \le L < H(p)+1$.
:::

:::proof
The lengths $\ell_i = \lceil\log(1/p_i)\rceil$ satisfy Kraft's inequality, since $2^{-\ell_i}\le p_i$ and the $p_i$ sum to $1$, so the cumulative construction of Kraft's converse realises them as a prefix code. Averaging the pointwise bounds $\log(1/p_i) \le \ell_i < \log(1/p_i)+1$ against $p$ gives $H \le L < H+1$. (This is the fundamental bound established earlier; it is repeated here because Shannon's lengths are the code it was proved for.)
:::

:::proposition[Fano's code is bracketed on both sides]{#fano-bracket}
Fano's code is a prefix code, so $L_{\text{Fano}} \ge H(p)$; and $L_{\text{Fano}} \ge L_{\text{Huffman}}$, so it is never better than the optimum.
:::

:::proof
The recursion assigns symbols to the leaves of a binary tree, so no codeword is a prefix of another, and the entropy lower bound for uniquely decodable codes gives $L \ge H$. The second inequality is Huffman optimality.
:::

:::remark[The upper bound for Fano's code]
That Fano's splitting also satisfies $L < H+1$ is classical, but its proof is a delicate induction over the splitting recursion — the difficulty is that a greedy split can be forced far from balance by a single dominant symbol — and we do not give it here. What the results above do give without extra work is the two-sided bracket $H \le L_{\text{Huffman}} \le L_{\text{Fano}}$ together with $L_{\text{Huffman}} < H+1$; for every distribution appearing in this chapter, $L_{\text{Fano}}$ is computed directly and checked against $H+1$.
:::

:::intuition
Fano's rule is "twenty questions with a balanced question": ask a yes/no question that splits the probability as evenly as you can, and the answer carries a full bit of information.

The reason it is not optimal is that the greedy split looks one level ahead. Balancing $0.52$ against $0.48$ at the top looks perfect, but it commits the most probable symbol to sharing its side with another, and so to a two-bit codeword.
:::

:::example[Fano's code on a dyadic source]
Construct Fano's code for $A\,0.5,\ B\,0.25,\ C\,0.125,\ D\,0.125$ (already sorted).
:::

:::solution
*Level 1.* Split $\{A\} \mid \{B,C,D\}$: masses $0.5$ and $0.5$, a perfect balance. Assign $0$ to the left, $1$ to the right. $A = 0$, finished.

*Level 2* on $\{B,C,D\}$ (prefix `1`). Split $\{B\}\mid\{C,D\}$: $0.25$ versus $0.25$. So $B = 10$, and $C,D$ carry the prefix `11`.

*Level 3* on $\{C,D\}$. Split $\{C\}\mid\{D\}$: $0.125$ each. $C = 110$, $D = 111$.

Lengths $1,2,3,3$ and

$$L = 0.5(1)+0.25(2)+0.125(3)+0.125(3) = 1.75 \text{ bits.}$$

**Sanity check.** $H = 1.75$ bits, so $L = H$ exactly, as the dyadic equality condition requires. Shannon's lengths agree here too: $\lceil\log(1/0.5)\rceil = 1$, $\lceil\log 4\rceil = 2$, $\lceil\log 8\rceil = 3$, $3$. And the Huffman code built earlier is the same code. On dyadic distributions all three constructions coincide.
:::

## Where Fano's Heuristic Loses to Huffman {#comparison}

<!-- section: comparison -->

Fano's code is top-down and greedy on *balance*; Huffman's is bottom-up and greedy on *rarity*. Only the second is optimal, and the gap is usually tiny but always in the same direction.

:::proposition[Fano's code is never better than Huffman's]{#sf-vs-huffman}
For every distribution, $L_{\text{Huffman}} \le L_{\text{Fano}}$, and the inequality is strict for some distributions.
:::

:::proof
Fano's construction yields a prefix code, and the Huffman code minimises expected length over all prefix codes by the optimality theorem, so $L_{\text{Huffman}} \le L_{\text{Fano}}$. Strictness is exhibited by the example below.
:::

:::example[A distribution where the heuristic is strictly worse]
Compare Fano's code and the Huffman code on $p = (0.35, 0.17, 0.17, 0.16, 0.15)$.
:::

:::solution
*Fano.* The most balanced consecutive split of the sorted list is $\{0.35, 0.17\}$ against $\{0.17,0.16,0.15\}$, i.e. $0.52$ against $0.48$; every other cut is further from $0.5$ ($0.35$ against $0.65$, or $0.69$ against $0.31$). The left pair splits once more, giving both symbols length $2$. On the right, the best cut is $\{0.17\}$ against $\{0.16,0.15\}$, so that symbol has length $2$ and the last two have length $3$. Lengths $(2,2,2,3,3)$:

$$L_{\text{Fano}} = 2(0.35+0.17+0.17) + 3(0.16+0.15) = 2(0.69) + 3(0.31) = 1.38+0.93 = 2.31 \text{ bits.}$$

*Huffman.* Merge $0.16+0.15 = 0.31$; then the two smallest are $0.17$ and $0.17$, merge to $0.34$; then $0.34 + 0.31 = 0.65$; then $0.65+0.35 = 1$. Depths: the $0.35$ symbol is at depth $1$, the other four at depth $3$. Lengths $(1,3,3,3,3)$:

$$L_{\text{Huffman}} = 0.35(1) + 3(0.17+0.17+0.16+0.15) = 0.35 + 3(0.65) = 0.35+1.95 = 2.30 \text{ bits.}$$

*Entropy.*

$$H = -\bigl(0.35\log 0.35 + 2(0.17\log 0.17) + 0.16\log 0.16 + 0.15\log 0.15\bigr) = 2.2328 \text{ bits.}$$

**Sanity check.** Both codes satisfy $H \le L < H+1$, i.e. $2.233 \le L < 3.233$ ✓, and Huffman wins by $0.01$ bits per symbol, as the proposition requires. The diagnosis is instructive: Fano's top-level balance is excellent ($0.52$ versus $0.48$) but it costs the most probable symbol a second bit, and $0.35$ bits of waste is not repaid by the better balance further down. Huffman's Kraft sums are equal ($1$ in both codes), so this is not a matter of wasted budget but of where the budget is spent.
:::

:::pitfall[Shannon's lengths are not Fano's lengths]
For the distribution above, Shannon's lengths are $\lceil\log(1/0.35)\rceil = 2$ and $\lceil\log(1/0.15)\rceil = 3$, giving $(2,3,3,3,3)$ and $L = 2.65$ — worse than both. The three constructions agree on dyadic distributions and diverge elsewhere, so "Shannon–Fano coding" is an ambiguous name; say which one you mean.
:::

:::theorem[Competitive optimality of the Shannon code]{#competitive-optimality}
Let $\ell(x) = \lceil\log(1/p(x))\rceil$ be the Shannon lengths and let $\ell'$ be the lengths of *any* other uniquely decodable code. Then for every $c \ge 1$,

$$\Pr\bigl( \ell(X) \ge \ell'(X) + c \bigr) \;\le\; 2^{-c+1} .$$

No competitor can beat the Shannon code by more than a few bits except with exponentially small probability — even though a competitor may beat it on average.
:::

:::proof
Using $\ell(x) < \log(1/p(x)) + 1$,

$$\Pr\bigl(\ell(X) \ge \ell'(X)+c\bigr) \le \Pr\Bigl(\log\tfrac1{p(X)} + 1 \ge \ell'(X)+c\Bigr) = \Pr\bigl(p(X) \le 2^{-\ell'(X)-c+1}\bigr).$$

Bounding the probability of the event by summing $p(x)$ over the strings in it, and on each such string using $p(x)\le 2^{-\ell'(x)-c+1}$,

$$\sum_{x:\,p(x)\le 2^{-\ell'(x)-c+1}} p(x) \;\le\; \sum_{x} 2^{-\ell'(x)-c+1} \;=\; 2^{-c+1}\sum_x 2^{-\ell'(x)} \;\le\; 2^{-c+1},$$

the last step by the Kraft–McMillan inequality for the competing code.
:::

This is the sense in which the Shannon code is hard to beat *per message* rather than on average: an opponent who does better on some strings must do much worse on others, and the worse cases carry most of the probability.

## Why the History Matters {#historical}

<!-- section: historical -->

Shannon's 1948 paper proved that $h$ was the compression limit and gave the lengths $\lceil\log(1/p)\rceil$ to show the limit was nearly attainable; Fano's contemporaneous splitting rule gave a practical recipe. Neither was optimal, and neither author claimed otherwise — the question "what is the best prefix code?" was left open, and Fano set it as a term project in his MIT information theory course in 1951.

David Huffman, a student in that course, chose the project over the final exam. After weeks of failing to improve the top-down approach, he inverted it: instead of asking which symbol gets which bit first, ask which two symbols are the *last* to be distinguished. The bottom-up merge fell out immediately, and with it the optimality proof.

Three lessons from the episode survive in the material of this chapter.

- **The right greedy direction is not obvious.** Both algorithms are greedy; only the bottom-up one has the exchange property that makes greed provably safe, and that property is exactly Lemma *Structure of an optimal code*.
- **Optimality within a class is not the end.** Huffman closed the prefix-code question, and the one-bit gap remained, which is what drove the development of arithmetic coding (Rissanen and Pasco, 1976) two decades later.
- **The old ideas do not disappear.** Shannon's lengths reappear as the length formula of arithmetic coding; Fano's balanced splitting reappears in the design of canonical and length-limited codes; and the cumulative-sum construction used for Shannon's code is exactly the interval arithmetic of the modern coder.

:::intuition
Shannon said: give common things short names. Fano said: here is a way to do it — halve the probability at each question. Huffman said: do it backwards, and here is the proof that nothing does better.

The remaining bit of waste came not from any of them but from the alphabet of output symbols: bits are indivisible. Arithmetic coding fixed that by giving up on codewords entirely.
:::

:::example[Reading the historical progression off one source]
For $p = (0.45, 0.30, 0.15, 0.10)$ line up Shannon's, Fano's and Huffman's codes and the entropy.
:::

:::solution
*Entropy.* $H = 1.782$ bits.

*Shannon.* $\ell = (2,2,3,4)$, $L = 0.45(2)+0.30(2)+0.15(3)+0.10(4) = 2.35$ bits.

*Fano.* The most balanced split is $\{0.45\}\mid\{0.30,0.15,0.10\}$ ($0.45$ against $0.55$; the alternative $\{0.45,0.30\}$ against $\{0.15,0.10\}$ is $0.75$ against $0.25$). Then $\{0.30\}\mid\{0.15,0.10\}$, then the last pair. Lengths $(1,2,3,3)$, $L = 0.45+0.60+0.45+0.30 = 1.80$ bits.

*Huffman.* Lengths $(1,2,3,3)$, $L = 1.80$ bits — identical to Fano's here.

**Sanity check.** $1.782 \le 1.80 \le 2.35 < 2.782$ ✓. Fano matches Huffman on this distribution and loses on the five-symbol example above, which is the honest summary of the heuristic: usually excellent, occasionally optimal, never guaranteed. Shannon's lengths are the weakest of the three because they round each symbol independently, ignoring how the rounding interacts across the alphabet.
:::

## Common Mistakes

- **Believing Fano's code is optimal.** It is not; the five-symbol example is a genuine counterexample, and the proposition above says the direction of the error is always the same.
- **Splitting by count instead of by mass.** The rule balances the *sum of probabilities* of the two groups, not the number of symbols in them.
- **Forgetting to sort first.** Fano's construction requires non-increasing probabilities and splits only into *consecutive* groups; splitting an unsorted list can produce a code far from optimal.
- **Conflating Shannon's lengths with Fano's algorithm.** They are different codes with different lengths, as the pitfall above shows.
- **Ignoring memory.** Like Huffman, Fano coding is symbol-by-symbol and blind to correlation; blocking or context modelling is required to capture it.
- **Assuming it is used in modern standards.** It is not. Where a simple prefix code is wanted, canonical Huffman is used; where the last fraction of a bit matters, arithmetic coding or ANS.

Every code so far has needed a model: Huffman needs the probabilities, arithmetic coding needs a conditional distribution per symbol, and only Lempel–Ziv managed without. A **universal** code is one that works for a whole *class* of sources at once, paying a price that vanishes per symbol. This last part makes the notion precise, exhibits the standard constructions, and proves that the price cannot be driven to zero at finite length.

## What Universality Means {#definition-universal}

<!-- section: definition-universal -->

:::definition[Redundancy of a code]{#code-redundancy}
Let $\mathcal{P}$ be a class of sources and let $C_n$ be a code on $\mathcal{X}^n$ with lengths $\ell_n$. For $P\in\mathcal{P}$ the **pointwise redundancy** on $x^n$ is

$$\rho_n(x^n, P) = \ell_n(x^n) - \log\frac{1}{P(x^n)},$$

the excess over the ideal codelength for $P$, and the **expected redundancy** is $R_n(P) = E_P[\rho_n(X^n,P)] = E_P[\ell_n] - H_P(X^n)$.
:::

:::definition[Universal code]{#universal-code}
A sequence of codes $\{C_n\}$ is **weakly universal** for the class $\mathcal{P}$ if for every $P \in \mathcal{P}$

$$\frac{1}{n}E_P\bigl[\ell_n(X^n)\bigr] \;\longrightarrow\; h(P),$$

the entropy rate of $P$; equivalently $R_n(P) = o(n)$ for every $P$. It is **strongly universal** (or *minimax*) if the convergence is uniform over $\mathcal{P}$:

$$\sup_{P\in\mathcal{P}} \frac{R_n(P)}{n} \;\longrightarrow\; 0 .$$

A code is **pointwise universal** if $\frac1n\rho_n(X^n,P)\to0$ almost surely under each $P$.
:::

Notice what universality is not. It is not "optimal for the unknown source at finite $n$" — no code is — and it is not a claim about any particular file. It is a statement that the *per-symbol* overhead of not knowing the source vanishes.

:::theorem[Codes are probability distributions]{#code-measure-duality}
Given any uniquely decodable code with lengths $\ell$, the assignment $Q(x) = 2^{-\ell(x)}/c$ with $c=\sum_x 2^{-\ell(x)} \le 1$ is a probability distribution, and $\ell(x) \ge \log(1/Q(x))$. Conversely, for any distribution $Q$ the lengths $\lceil\log(1/Q(x))\rceil$ define a prefix code.

Consequently designing a universal code *is* designing a single distribution $Q$ that is close to every $P$ in the class simultaneously, and the redundancy is

$$R_n(P) \;=\; D\bigl(P^{(n)} \,\|\, Q^{(n)}\bigr) + O(1).$$
:::

:::proof
The first claim is Kraft–McMillan plus normalisation; the second is Kraft's converse, as used for the Shannon code. For the redundancy formula, take $\ell_n(x^n) = \lceil\log(1/Q(x^n))\rceil$, so that $\ell_n < \log(1/Q(x^n)) + 1$, and average under $P$:

$$E_P[\ell_n] \;<\; \sum_{x^n} P(x^n)\log\frac{1}{Q(x^n)} + 1 \;=\; H_P(X^n) + D\bigl(P\,\|\,Q\bigr) + 1,$$

by the cost-of-the-wrong-model identity. Subtracting $H_P(X^n)$ gives $R_n(P) \le D(P\|Q) + 1$, and the matching lower bound $R_n(P)\ge D(P\|Q) - O(1)$ follows from the entropy bound applied to the code's own induced distribution.
:::

This duality is the organising idea of the whole subject: a universal compressor is a *single* distribution over files that hedges across a class of sources, and its worst-case cost is a divergence.

:::intuition
A universal compressor is a packing service that is not told what is in your luggage. It watches the first few items, forms a theory, and keeps revising. The theory is wrong at first, which costs bits — but the number of wasted bits grows like $\log n$, not like $n$, so the per-item waste goes to zero.

The formal version of "forming a theory" is Bayesian: put a prior on the class of sources, let $Q$ be the resulting mixture, and the redundancy becomes the cost of the prior.
:::

:::example[Weak universality of Lempel–Ziv]
Which class is LZ78 universal for, in which sense, and what is known about its redundancy?
:::

:::solution
*Class.* All stationary ergodic processes on a finite alphabet.

*Sense.* Pointwise: $\frac1n\ell(X^n)\to h$ almost surely, by the LZ optimality theorem. Pointwise convergence implies weak universality by dominated convergence, the codelength being bounded by $\log D + o(1)$ per symbol.

*Redundancy.* Slow. For an i.i.d. or finite-order Markov source the LZ78 redundancy is of order $n\log\log n/\log n$ in total, i.e. about $\log\log n/\log n$ per symbol; for $n = 10^{6}$ that is roughly $4.3/20 \approx 0.2$ bits per symbol.

**Sanity check.** Compare with the $O(\log n)$ *total* redundancy of a mixture code for a parametric class: at $n = 10^{6}$ that is about $10$ bits in total, versus LZ's $200{,}000$. The comparison is fair only where the parametric model is right — LZ pays for covering a vastly larger class, and for asking nothing of the user.
:::

## The Standard Constructions {#examples}

<!-- section: examples -->

Three families of universal code recur, and they cover the practical ground.

**Integer codes.** These are universal for the class of all distributions on $\mathbb{N}$ with decreasing probabilities, and are the building block for headers, lengths and dictionary indices.

:::definition[Elias gamma and delta codes]{#elias-codes}
The **Elias gamma** code writes a positive integer $n$ as $\lfloor\log n\rfloor$ zeros, followed by the $\lfloor\log n\rfloor + 1$ bits of $n$ in binary. The **Elias delta** code replaces the unary prefix by the gamma code of $\lfloor\log n\rfloor + 1$.
:::

:::proposition[Lengths of the Elias codes]{#elias-lengths}
Gamma uses $2\lfloor\log n\rfloor + 1$ bits and delta uses $\lfloor\log n\rfloor + 2\lfloor\log(\lfloor\log n\rfloor+1)\rfloor + 1$ bits; both are prefix codes, and delta is within $1+o(1)$ of the ideal $\log n$ bits.
:::

:::proof
For gamma, the unary prefix of $\lfloor\log n\rfloor$ zeros terminated by the leading $1$ of the binary expansion tells the decoder how many further bits to read, so the code is prefix-free, and the total is $\lfloor\log n\rfloor + (\lfloor\log n\rfloor+1)$. For delta, the same argument applies with the unary prefix replaced by a gamma-coded length, whose own length is $2\lfloor\log(\lfloor\log n\rfloor+1)\rfloor+1$; the payload contributes the remaining $\lfloor\log n\rfloor$ bits. The ratio of the delta length to $\log n$ tends to $1$, since $\log\log n = o(\log n)$.
:::

**Mixture and plug-in codes.** These are universal for parametric classes, and achieve the best possible redundancy.

:::definition[Krichevsky–Trofimov estimator]{#kt-estimator}
For a binary i.i.d. source of unknown bias, the **KT estimator** predicts the next symbol after $a$ zeros and $b$ ones by

$$\hat p(1 \mid a,b) = \frac{b + \tfrac12}{a+b+1},$$

and feeding these predictions to an arithmetic coder produces the KT code. It is the Bayesian mixture over the bias with a $\mathrm{Beta}(\tfrac12,\tfrac12)$ (Jeffreys) prior.
:::

:::theorem[KT redundancy]{#kt-redundancy}
For every $\theta \in [0,1]$, the KT code applied to an i.i.d. binary source of bias $\theta$ has total redundancy

$$R_n(\theta) \;\le\; \tfrac12 \log n + 2 \text{ bits},$$

uniformly in $\theta$ — a *total* overhead, not a per-symbol one, so the per-symbol overhead is $O(\log n / n)$.
:::

:::proof
We sketch the standard argument. The KT probability of a string with $a$ zeros and $b$ ones is the mixture $Q(x^n) = \int_0^1 \theta^{b}(1-\theta)^{a}\,w(\theta)\,d\theta$ with the Jeffreys prior $w(\theta) = \pi^{-1}\theta^{-1/2}(1-\theta)^{-1/2}$. Laplace's method applied to this integral gives

$$\log\frac{1}{Q(x^n)} \;\le\; \log\frac{1}{\hat\theta^{b}(1-\hat\theta)^{a}} + \tfrac12\log n + O(1)$$

where $\hat\theta = b/n$ is the maximum-likelihood bias, and the first term is at most $\log(1/\theta^b(1-\theta)^a)$ for the true $\theta$ because $\hat\theta$ maximises the likelihood. Taking expectations under $\theta$ and adding the arithmetic coder's two bits gives the claim. The full argument evaluates the Beta integral exactly; it is carried out in the source-coding literature and we do not reproduce it.
:::

**Context models.** Context Tree Weighting (CTW) mixes KT estimators over all tree-structured context models up to a depth $d$, achieving redundancy $O(|S|\log n)$ for any tree source with $|S|$ states — again a logarithmic total. Prediction by Partial Matching (PPM) is the heuristic cousin that dominated text compression benchmarks before context mixing (PAQ, cmix) and, more recently, neural predictors.

:::example[Counting the cost of not knowing the bias]
A binary file of $n = 10^{6}$ symbols comes from an i.i.d. source of unknown bias $\theta = 0.1$. Compare the ideal length, the KT length, and the length produced by wrongly assuming $\theta = 0.5$.
:::

:::solution
*Ideal.* $H(0.1) = 0.469$ bits/symbol, so $nH = 469{,}000$ bits.

*KT.* At most $nH + \tfrac12\log n + 2 = 469{,}000 + \tfrac12(19.93) + 2 \approx 469{,}012$ bits. The overhead is $12$ bits — about $2.6\times10^{-5}$ bits per symbol.

*Wrong fixed model.* Assuming a fair coin costs $H + D(p\|q) = 1$ bit per symbol, i.e. $1{,}000{,}000$ bits.

**Sanity check.** The wrong fixed model throws away $1{,}000{,}000 - 469{,}000 = 531{,}000$ bits; the universal coder recovers all but $12$ of them. Twelve bits against half a megabit is the practical case for universal coding in one line.
:::

## The Price of Universality {#limitations-universal}

<!-- section: limitations-universal -->

Universality is not free, and the cost has an exact asymptotic form. The intuition is a counting one: a code that must be ready for $|\mathcal{P}|$ essentially different sources has to reserve short codewords for the typical set of each, and typical sets of different sources are disjoint.

:::definition[Minimax redundancy]{#minimax-redundancy-def}
The **minimax redundancy** of a class $\mathcal{P}$ at block length $n$ is

$$R_n^{*} = \min_{Q}\ \max_{P\in\mathcal{P}}\ D\bigl(P^{(n)}\,\|\,Q^{(n)}\bigr),$$

the least worst-case excess achievable by any single coding distribution $Q$.
:::

:::theorem[Rissanen's bound for parametric classes]{#minimax-redundancy}
For the class of i.i.d. distributions on an alphabet of size $m$ — a $k = m-1$ parameter family — the minimax redundancy satisfies

$$R_n^{*} \;=\; \frac{m-1}{2}\log n + O(1) \text{ bits.}$$

More generally, for a smooth $k$-parameter class the minimax redundancy is $\tfrac{k}{2}\log n + O(1)$: **every parameter costs half a logarithm.** No universal code for such a class can do better, and mixture codes such as KT and CTW attain it.
:::

:::remark[On the proof]
The upper bound is the mixture argument sketched for the KT estimator, applied with Jeffreys' prior in $k$ dimensions; the constant in $O(1)$ is the logarithm of the volume of the parameter space in the Fisher metric. The lower bound is Rissanen's theorem, proved by a counting argument: the parameter space contains about $n^{k/2}$ distributions that are statistically distinguishable at sample size $n$, and no single $Q$ can be close to all of them at once. Both halves are beyond the scope of this chapter; we state the result and use it.
:::

:::corollary[Half a bit per parameter per doubling]{#half-log}
Doubling the file length adds $k/2$ bits to the minimax redundancy — so for fixed $k$ the *per-symbol* cost of universality decays like $\tfrac{k\log n}{2n}$, and vanishes.
:::

:::proof
Replace $n$ by $2n$ in the theorem: the redundancy changes by $\tfrac k2\log 2 = k/2$ bits. Dividing the total by $n$ gives the per-symbol claim.
:::

:::theorem[Most strings are incompressible by any code]{#incompressible}
For any uniquely decodable code on $\{0,1\}^n$ and any $k\ge1$, fewer than a fraction $2^{-k+1}$ of the $2^n$ inputs receive codewords shorter than $n-k$ bits. In particular, no universal code — however clever, however adaptive — compresses more than a negligible fraction of all files.
:::

:::proof
This is the no-free-lunch theorem applied to the encoder, which is injective by unique decodability: at most $2^{n-k+1}-1$ binary strings have length less than $n-k+1$, so at most that many inputs can receive them.
:::

The two theorems together delimit the subject. Universality is possible because real data is not uniform over $\{0,1\}^n$ — it lives in the typical set of some low-entropy source — and the only cost of not knowing *which* source is logarithmic. But the moment the data really is uniform, no amount of adaptivity helps, because the obstruction is counting, not ignorance.

:::remark[Kolmogorov complexity: the ultimate universal code]
One can define the complexity $K(x)$ of a string as the length of the shortest program that prints it on a fixed universal machine. This is universal in the strongest sense — $K(x) \le \ell(x) + O(1)$ for every computable code $\ell$ — and for a computable source $E[K(X^n)] = H(X^n)+O(\log n)$. It is also **uncomputable**: no algorithm computes $K$, by a diagonal argument closely related to the halting problem. Kolmogorov complexity is therefore the correct theoretical endpoint of this chapter and useless as an engineering target. The practical hierarchy — Huffman, arithmetic, LZ, CTW — is a sequence of computable approximations to an ideal that cannot be reached.
:::

:::example[Sizing the minimax penalty for a real alphabet]
A compressor must handle an unknown memoryless source over the $256$ byte values. How many extra bits must it pay on a $1$ MB file, and on a $1$ kB file?
:::

:::solution
Here $m = 256$, so $k = m-1 = 255$ parameters.

*1 MB.* The symbols are bytes, so $n = 10^{6}$. The penalty is

$$\frac{255}{2}\log_2 10^{6} = 127.5 \times 19.93 \approx 2541 \text{ bits} \approx 318 \text{ bytes},$$

or $0.03\%$ of the file.

*1 kB.* $n = 1024$: $127.5 \times 10 = 1275$ bits $\approx 159$ bytes, which is $16\%$ of the file.

**Sanity check.** The penalty grows only logarithmically in $n$ while the file grows linearly, so the relative cost falls by a factor of about $500$ between the two sizes — which is precisely why compressors have a minimum useful file size, and why archive formats compress many small files as one stream ("solid" archives) rather than separately.
:::

## Common Mistakes

- **Thinking a universal code achieves the entropy exactly on every file.** It achieves $nh + o(n)$; on short files the $o(n)$ term dominates and compression can be negative.
- **Confusing universal with optimal-for-the-unknown-source.** Rissanen's bound says a strictly positive minimax redundancy is unavoidable at every finite $n$.
- **Assuming Lempel–Ziv is the best universal code.** It is universal over a far larger class than CTW, and correspondingly slower to converge: $O(n\log\log n/\log n)$ against $O(\log n)$ total redundancy on parametric classes.
- **Forgetting that the class must be specified.** A code universal for i.i.d. sources need not be universal for sources with long memory; "universal" without a class is meaningless.
- **Restricting the term to integer codes.** Elias codes are the classic examples, but in modern usage a universal *compressor* is the whole model-plus-coder pipeline.
- **Believing adaptivity defeats the counting bound.** The incompressibility theorem quantifies over every injective encoder. Adaptive, neural or otherwise, almost all strings stay incompressible.
