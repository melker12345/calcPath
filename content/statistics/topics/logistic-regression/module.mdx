# Logistic Regression

Logistic regression is the go-to method for modeling binary outcomes (yes/no, success/failure, disease/no disease). Instead of predicting the value of $y$ directly, it predicts the *probability* that $y=1$.

The key idea is the logistic (sigmoid) function, which transforms any real number into a probability between 0 and 1. This gives us a principled way to do classification while still allowing familiar regression-style interpretation via log-odds (logits).

It is the foundation of many modern machine learning classifiers and is widely used in medicine, marketing, credit scoring, and the social sciences.

## Why Linear Regression Fails for Binary Data

<!-- section: why-logistic -->

If $y$ is 0 or 1, fitting a linear model $\hat{y} = b_0 + b_1 x$ can produce predictions outside $[0,1]$. A predicted probability of 1.3 or -0.2 is nonsensical.

The variance of a binary outcome is $p(1-p)$, which is not constant — it is largest when $p=0.5$ and smallest near 0 or 1. This violates the constant variance assumption of ordinary linear regression.

The relationship between a predictor and a probability is typically S-shaped (sigmoid), not linear.

:::intuition
Trying to use ordinary linear regression on yes/no data is like using a ruler to measure temperature in a system that only has two states: ice or steam. The ruler will give you numbers outside the possible range and the errors won't behave nicely.
:::

:::example[Linear regression predicting an impossible probability]
Suppose we fit a straight line to predict whether a loan defaults ($y=1$) from income (in \$1000s), and get $\hat{y} = 0.9 - 0.01 x$.
:::

:::solution
1. For a low earner with $x = 20$: $\hat{y} = 0.9 - 0.01 \cdot 20 = 0.9 - 0.2 = 0.7$. Fine so far — this reads as a 70% chance.
2. For a high earner with $x = 100$: $\hat{y} = 0.9 - 0.01 \cdot 100 = 0.9 - 1.0 = -0.1$. A probability of $-0.1$ is impossible.
3. Sanity check: a valid probability must lie in $[0,1]$, but the line is unbounded, so far enough out in either direction it *must* leave $[0,1]$. This is the structural failure logistic regression fixes by squashing the output through the sigmoid.
:::

## The Logistic Model

<!-- section: model -->

First, some vocabulary. The **odds** of an event are the ratio of the probability it happens to the probability it doesn't: $\text{odds} = \frac{p}{1-p}$. Odds of 3 (often written "3 to 1") mean the event is three times as likely to occur as not. Because $p$ is trapped in $[0,1]$ but odds range over $(0, \infty)$, and the **log-odds** $\log\!\left(\frac{p}{1-p}\right)$ range over all of $(-\infty, \infty)$, the log-odds live on exactly the same unbounded scale as a linear predictor. That is the trick: we do the linear modeling on the log-odds scale, where nothing can go out of bounds.

We model the *log-odds* (logit) as a linear function: $\log\left(\frac{p}{1-p}\right) = b_0 + b_1 x_1 + \dots + b_k x_k$ (valid for $0 < p < 1$; the logit is undefined at $p=0$ and $p=1$).

Solving for the probability gives the logistic (sigmoid) function: $p = \frac{1}{1 + e^{-(b_0 + b_1 x_1 + \dots + b_k x_k)}}$.

The coefficient $b_j$ now has a very useful interpretation: it is the change in the *log-odds* of the outcome for a one-unit increase in $x_j$, holding other variables constant. Exponentiating gives the odds ratio: $e^{b_j}$ is the multiplicative change in the odds.

For example, if $b_1 = 0.693$ for a binary predictor, then $e^{0.693} \approx 2$, meaning the odds of the outcome are doubled when that predictor is present (holding others fixed).

:::intuition
Instead of predicting the probability directly, logistic regression predicts the 'log-odds' on a straight line. The S-curve (sigmoid) then converts those log-odds back into a clean probability between 0 and 1. The coefficients tell you how much each variable multiplies the odds of the event happening.
:::

:::example[Odds and probability convert both ways]
Say the probability a customer buys is $p = 0.8$. The odds are $\frac{p}{1-p} = \frac{0.8}{0.2} = 4$ — a "4 to 1" chance of buying.
:::

:::solution
1. Going the other way, suppose we are told the odds of an event are $3$. Solve $\frac{p}{1-p} = 3$: multiply out to get $p = 3(1-p) = 3 - 3p$, so $4p = 3$ and $p = 0.75$.
2. Sanity check: $p = 0.75$ gives odds $\frac{0.75}{0.25} = 3$ ✓, and $p = 0.8$ gives back $p = \frac{4}{1+4} = 0.8$ ✓ (using $p = \frac{\text{odds}}{1+\text{odds}}$).
:::

:::example[From coefficients to a predicted probability]
Model for heart attack risk: $\text{logit}(p) = -4.2 + 0.8 \cdot \text{smoker} + 0.05 \cdot \text{age}$.
:::

:::solution
1. Take a 50-year-old smoker: plug in $\text{smoker}=1$, $\text{age}=50$. The logit is $-4.2 + 0.8(1) + 0.05(50) = -4.2 + 0.8 + 2.5 = -0.9$.
2. Convert the log-odds back to a probability with the sigmoid: $p = \frac{1}{1 + e^{-(-0.9)}} = \frac{1}{1 + e^{0.9}} = \frac{1}{1 + 2.46} \approx 0.29$.
3. Sanity check: the logit is negative, so we expect $p < 0.5$, and indeed $0.29 < 0.5$ ✓.
:::

:::example[Interpreting an odds ratio]
Using the same heart attack model, focus on the 'smoker' variable, whose coefficient is $b = 0.8$.
:::

:::solution
1. The odds ratio is $e^{b} = e^{0.8} \approx 2.23$.
2. Interpretation: holding age fixed, smokers have $2.23$ times the odds of a heart attack compared with non-smokers.
3. Sanity check via the two logits: for a 50-year-old non-smoker the logit is $-4.2 + 0 + 2.5 = -1.7$, versus $-0.9$ for the smoker above. The difference is $-0.9 - (-1.7) = 0.8 = b$, and exponentiating that log-odds difference gives $e^{0.8} \approx 2.23$ — the same odds ratio ✓.
:::

## Estimation and Inference

<!-- section: estimation -->

Parameters are estimated by maximum likelihood (not least squares). Each observation contributes its predicted probability of the outcome that actually occurred: $p_i$ if $y_i = 1$ and $1 - p_i$ if $y_i = 0$. Assuming the observations are independent, the likelihood is the product of these contributions, $L = \prod_i p_i^{y_i}(1 - p_i)^{1 - y_i}$, and we choose the coefficients that make it as large as possible (equivalently, we maximize its logarithm, the log-likelihood).

There is no closed-form solution — we use iterative numerical methods (Newton-Raphson or iteratively reweighted least squares).

Wald tests (similar to t-tests) and likelihood ratio tests are used for inference on individual coefficients and groups of coefficients.

Model fit is assessed with deviance, pseudo-$R^2$ measures (McFadden, Cox-Snell, Nagelkerke), and classification tables (sensitivity, specificity, ROC curves). Once we have predicted probabilities, we turn them into 0/1 predictions by comparing to a **threshold** (0.5 by default). **Sensitivity** is the fraction of true positives caught, and **specificity** is the fraction of true negatives correctly cleared; an **ROC curve** traces sensitivity against $1 - \text{specificity}$ as the threshold sweeps from 1 down to 0.

:::intuition
Instead of minimizing squared errors, logistic regression chooses the coefficients that make the observed data as probable as possible under the model. It's like tuning a recipe until the outcomes you actually saw become the most likely ones the model would have predicted.
:::

:::example[Computing a likelihood]
Three independent observations with outcomes $y = (1, 0, 1)$. A candidate model predicts probabilities of "1" of $p = (0.8,\ 0.3,\ 0.6)$.
:::

:::solution
1. Each point contributes the probability of what actually happened: obs 1 was a 1, contributes $0.8$; obs 2 was a 0, contributes $1 - 0.3 = 0.7$; obs 3 was a 1, contributes $0.6$.
2. Multiply (independence): $L = 0.8 \times 0.7 \times 0.6 = 0.336$.
3. Sanity check that this beats a know-nothing model that predicts $p = 0.5$ for everyone: $L = 0.5 \times 0.5 \times 0.5 = 0.125$. Since $0.336 > 0.125$, the first model explains the data better ✓ — and maximum likelihood is the search for the coefficients that push $L$ as high as it will go.
:::

:::example[How the threshold trades sensitivity for specificity]
Five patients, actual disease status ($1$ = disease) and model-predicted probabilities:
:::

:::solution
| Patient | Actual $y$ | Predicted $p$ |
|--------:|:----------:|:-------------:|
| 1 | 1 | 0.90 |
| 2 | 1 | 0.60 |
| 3 | 0 | 0.40 |
| 4 | 1 | 0.35 |
| 5 | 0 | 0.20 |

At threshold $0.5$ (predict disease if $p \ge 0.5$): flagged = patients 1, 2. Of the three true cases (1, 2, 4), we catch 2, so sensitivity $= 2/3 \approx 0.67$; both true non-cases (3, 5) are correctly cleared, so specificity $= 2/2 = 1$.
Lower the threshold to $0.3$: flagged = patients 1, 2, 3, 4. Now all three true cases are caught, sensitivity $= 3/3 = 1$, but patient 3 (a non-case) is now a false positive, so specificity $= 1/2 = 0.5$.
Sanity check: dropping the threshold raised sensitivity ($0.67 \to 1$) and lowered specificity ($1 \to 0.5$), exactly the trade-off the ROC curve traces out ✓.
:::

## Assumptions and Diagnostics

<!-- section: assumptions -->

Linearity in the logit: the log-odds must be a linear function of the predictors (check with LOWESS smoothed plots of logit vs continuous predictors).

Independence of observations (same as linear regression).

No perfect separation (complete or quasi-complete) — when a predictor perfectly predicts the outcome, the maximum likelihood estimates become infinite.

Large sample sizes are generally needed for reliable inference (rule of thumb: at least 10 events per predictor variable).

:::intuition
The key new assumption is that the relationship is linear on the log-odds scale, not on the probability scale. A variable can have a very nonlinear-looking effect on probability but still be perfectly linear in log-odds.
:::

:::example[Spotting perfect separation]
Suppose every patient with cholesterol below $200$ is healthy ($y=0$) and every patient at or above $200$ is sick ($y=1$), with no overlap.
:::

:::solution
1. The likelihood is maximized by making the fitted probability jump from $0$ to $1$ right at $200$, which requires an infinitely steep sigmoid — i.e. the slope coefficient is driven toward $\pm\infty$.
2. Symptom you would actually see: the software warns of non-convergence, or reports a huge coefficient with a gigantic standard error (e.g. $b = 34$ with SE $= 12000$).
3. Fix: this is *complete separation*. Remedies include penalized/Firth logistic regression, dropping or combining the offending predictor, or gathering data that overlaps the boundary. Contrast with *quasi-complete separation*, where the split is perfect only along a tie.
:::

:::example[Applying the events-per-variable rule]
You want to fit a model with $5$ predictors. The rule of thumb asks for at least $10$ events (occurrences of the *less common* outcome) per predictor, so you need about $10 \times 5 = 50$ events.
:::

:::solution
1. Your dataset has $600$ patients but only $40$ have the disease. The binding count is the events ($40$), not the total sample, giving $40 / 5 = 8$ events per variable — below $10$.
2. Conclusion: with only $8$ events per predictor the estimates and their standard errors may be unstable; you should reduce the number of predictors (to at most $4$) or collect more cases before trusting the inference.
:::

## Extensions and Related Models

<!-- section: extensions -->

Multinomial logistic regression handles more than two outcome categories.

Ordinal logistic regression is appropriate when the outcome has a natural ordering (e.g., low/medium/high satisfaction).

Regularized logistic regression (lasso, ridge) is very common in high-dimensional settings (genomics, text classification).

Logistic regression is a special case of generalized linear models (GLMs) with a binomial distribution and logit link function.

:::intuition
Once you understand binary logistic regression, the extensions are natural: predicting among several categories (multinomial), respecting order in the categories (ordinal), or adding shrinkage when you have thousands of predictors.
:::

:::example[Multinomial prediction via softmax]
A model for three fruit classes produces raw scores (logits) $z = (z_{\text{apple}}, z_{\text{banana}}, z_{\text{cherry}}) = (1, 2, 0)$ for one item.
:::

:::solution
1. Softmax exponentiates and normalizes so the class probabilities sum to 1: compute $e^{1} \approx 2.72$, $e^{2} \approx 7.39$, $e^{0} = 1$, with sum $2.72 + 7.39 + 1 = 11.11$.
2. Divide each by the sum: apple $\approx 2.72/11.11 = 0.245$, banana $\approx 7.39/11.11 = 0.665$, cherry $\approx 1/11.11 = 0.090$.
3. Sanity check: the three probabilities add to $0.245 + 0.665 + 0.090 = 1.000$ ✓, and the largest logit (banana) gets the largest probability ✓. Binary logistic regression is exactly this with two classes, where softmax collapses to the ordinary sigmoid.
:::

## Common Mistakes

- Interpreting the coefficients as changes in probability instead of changes in log-odds or odds ratios.
- Reporting only accuracy on imbalanced data (a model that always predicts the majority class can have high accuracy but be useless).
- Ignoring the linearity-in-the-logit assumption for continuous predictors.
- Using logistic regression when the outcome is not truly binary or when events are not independent (e.g., clustered data).
- Over-interpreting odds ratios as risk ratios when the outcome is common (odds ratios exaggerate effects when baseline risk is high).
